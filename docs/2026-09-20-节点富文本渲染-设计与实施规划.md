## 1. 定位

### 1.1 一句话定义

**摘要型节点 = 节点盒内、标题之下,以富文本渲染一段概括内容(摘要)的节点形态。**

- **内容载体**:复用现有 `desc` 字段(协议 §5.2「幕布风格描述」)—— 摘要区 = desc 槽位的渲染升级,**不新增键**;
- **归属**:摘要属于**节点本体**(随节点缩放、参与布局、随复制/升降格一起走),区别于"附着物"内容(note 卡片、悬停浮窗);
- **本次交付**:摘要区的**行内富文本渲染**;标题行内富文本作为 P2(同一套 token 能力的一体两面)。

### 1.2 用户故事(自用场景)

| # | 场景 | 期望 |
|---|---|---|
| U1 | 在节点下写「全期望公式:**E[X]=E[E[X\|Y]]**,用 `sympy` 验证 4 组分布」 | **加粗**与 `code` 按样式渲染,而不是满屏 `**` 与反引号 |
| U2 | 摘要里嵌 `[2.5 常用连续分布](cid:c12)` | 可点、可跳转、失效幽灵态(**现有能力,必须零回归**) |
| U3 | 标题里写重点 | 标题也支持行内富文本(加粗 / 等宽 / 链接样式,P2) |

### 1.3 成功判据

1. `**加粗**`、`` `code` ``、`[名](锚)` 在**显示态**按样式渲染;编辑态保持源码(与 note.md「源文/预览」同哲学)。
2. **布局零错位**:渲染宽高与 measure 预留一致(「度量与渲染同源」纪律)。
3. 存量文档:纯文本零变化;含成对标记的文本开始按富文本渲染(预期语义,列观察项清单)。

### 1.4 非目标(Non-goals)

- ❌ **不新增节点类型 / 字段**(不引入 `summary` 键、不做"显式型标记")—— 先验证形态价值,治理(与「类型设置」批次)后置;
- ❌ **不做块级内容**(列表 / 引用 / 代码块 / 表格)—— P3 单独立项;
- ❌ **不改**字号 / 行数上限 / 折行策略(desc 维持「不自动折行、16 行软上限、内部滚动」);
- ❌ **不碰**导出富文本保真(SVG/PNG 导出本就简化)、不碰 Canvas 后端(ADR-0006 边界);
- ❌ **不做**自动摘要生成(从 note 提取首段等"魔法"不引入)。

## 2. 解读校准(与用户草稿的对齐,详见 §7)

| 读法 | 处理 |
|---|---|
| ① 盒内富文本内容(内容型节点起步) | **即本方案**:先"行内",块级后置 |
| ② desc 富文本升级 | **即本方案**:摘要区载体 = desc |
| ③ XMind 式"分组摘要"(给一组节点加概括括号) | **明确排除**;若要,另立项(涉及分组/括号/布局,成本结构完全不同) |
| ④ 独立 `summary` 键(与 desc 分工) | 备选方案;代价见 §7-D1(全链路新建,+2~4 天) |

## 3. 现状盘点(设计所依赖的事实)

### 3.1 地基:半成品与先例(全部已就位)

| 事实 | 位置 |
|---|---|
| 行内 tokenizer:`**bold**` / `` `code` `` / `[label](url)` + 样式宽度系数(1.05 / 0.95) | `kernel/layout/inline.ts:6-69` |
| 标题测量已接 token:行宽 = max(纯文本宽, token 加权宽)——**渲染后不会溢出盒宽** | `kernel/layout/nodeLayout.ts:97-100` |
| `metrics.tokens` 逐行产出(每行一个 token 数组),**内核零改动即可消费** | `nodeLayout.ts:136 / 181 / 203` |
| desc 全链路:度量装饰器 → overlay → 编辑 → 快捷键 | `react/demo/pipeline.ts:155-173`、`chrome/DescBlock.tsx`、`render/overlays.tsx:41-113` |
| 链接已渲染:三态 + 可点 + 幽灵态(URL 形态拒认 / 转义 / 嵌套作废) | `chrome/TextLinkSpans.tsx:34-73`、`edit/textLinks.ts:59-187` |
| 编辑态 = 源码先例:desc textarea;note.md「源文 / 预览」双态 | `DescBlock.tsx:308-355`、`chrome/NoteBackEditor.tsx` |

**结论:本功能是"给已就位的 token 管线接上消费方",不是从零构建。** 这也是它排在第一位的核心理由:四组扩展里成本最低、收益最直接。

### 3.2 硬约束(必须遵守)

1. **desc 现行语义**:不自动折行、长了横向撑宽盒(`DescBlock.tsx:166-174`);显式 `\n` 才换行;16 行软上限、超出内部滚动;行高恒 15、字号随层级 10/8.5。
2. **度量与渲染同源**:overlay 几何与 measure 装饰器共用同一估算函数(`overlays.tsx:77-85` 注释纪律);描述区宽度 = 节点盒宽(由 `estimateDescWidth` 撑宽决定,`overlays.tsx:101`)。
3. **性能纪律**:NodeG 是 memo 热路径(纯平移 0 重渲染)—— 改其渲染必须跑 `tests/mapview-pan-memo.test.tsx` 回归。
4. **预算 / lint 计数纪律**:新代码零新增 bang / any;改动后逐数核对(lint 计数含测试文件)。
5. **零硬编码视觉值**:新增样式走 token / CHROME(必要时在 CHROME 增键,如 code 底色)。

### 3.3 存量数据形态(来自真实文件)

`apps/canvas/src/demo/829-notes-reconstruction-workflow.mm.md`:desc 已是"成段摘要"形态(2~3 行 `\n` 分隔,中文长句);单 `*` 用例(`*-SN-*.md`)不会误触发 `**` 解析。→ **升级收益直接命中真实日用法。**

## 4. 设计方案

### 4.1 数据面:零改动

- 摘要 = `note.desc`(string,`\n` 转义);不新增键、parser / serializer / roundtrip 全部不动;
- 编辑写回仍是 desc 原文(含标记);canonical / 幂等 / 诊断契约不受影响;
- 若未来要"显式摘要标记",并入「类型设置」批次统一裁决 —— 现在做属于治理前置。

### 4.2 渲染面(核心交付)

**A. 摘要区(DOM · P1 主交付)**

- 新增 `InlineRichText`(`chrome/InlineRichText.tsx`),管线:

  ```
  parseTextLinks(text, root)          ← 链接段:一行不改(状态/转义/URL 策略/点击语义)
    └─ text 段 → tokenizeInline()     ← 新增:strong / code 渲染
  ```

  - **链接契约原样保留**(L 批次已验收行为零回归);strong / code 是纯增量。
  - 样式映射(首版;实现时附两版对比稿校准):

    | token | DOM 呈现 | 备注 |
    |---|---|---|
    | strong | 增重(`base + 150`,钳 800)+ 同色 | 中文小字下若不可辨,备选"增重 + 微提亮" |
    | code | 等宽字体 + 浅底色块 + 圆角 + 同字号 | 底色走 CHROME 新键(零硬编码) |
    | link | 现状不变(色 + 下划线 + 三态) | 已验收能力 |

  - 已知边界(记录在案,不阻塞):
    - 跨行标记不识别(desc 按 `\n` 分行,标记须在同一行内闭合);
    - 标记不嵌套:`**[a](x)**` → 字面 `**` + 链接;`[**x**](y)` → label 原样;
    - 标题与摘要极端嵌套的呈现差异(两套管线):后续统一收敛项。
- **宽度估算同步(同一提交内)**:`estimateDescWidth` 从"原文宽"改为"**渲染宽**":
  `max(char(line), inlineWidth(tokenizeInline(line), char))` 逐行取最大 —— 等价于内核 `lineWidthOf` 口径(`nodeLayout.ts:97-100`),`tokenizeInline` / `inlineWidth` 均已从 kernel 导出,直接复用。
  - 影响:纯文本行**结果不变**;含标记行按渲染后文本估算(标记不占宽 → 盒宽更准)。
  - overlay 无需改:其宽度取自盒宽(measure 撑宽后自然对齐)。

**B. 标题行内富文本(SVG · P2)**

- `NodeG.tsx:275-287`:每行 `<text>{line}</text>` → 消费 `metrics.tokens[i]` 渲染 `<tspan>` 序列:
  - strong → `font-weight` 增档;code → 等宽 `font-family` + 变色;link → 变色 + 下划线(`text-decoration`)。
  - **内核实零改动**(tokens 现成;盒宽双算已兜底);SVG 内 code 暂不做底色块(token 级 x 偏移度量未产出,列入后续可选)。
  - 链接**点击**:首版仅样式;若要,参照 L 批次 stopPropagation 纪律,单列 +0.5 天。
- 编辑 / 选中 / 拖拽 / LOD 路径不变(`noText` 逻辑不涉及)。

**C. 消费面清单(统一组件的影响面,逐面核验)**

`TextLinkSpans` 现有 5 个消费面,升级后逐一核对(默认跟随,如某面需要纯文本个别处理):
`DescBlock`(P1 接线)、`NotePopover`(note 序列 + note_text,`:397 / :475`)、`NoteGrowthPanel`(`:153 / :188`)。

### 4.3 编辑面:源码态(不变)

- desc textarea / note 编辑 / 提交键位全部不动;`**` 与 `` ` `` 编辑态可见、提交后渲染;
- 可选 polish:desc 编辑 placeholder 附语法提示;不做富编辑(WYSIWYG)。

### 4.4 一致性检查表(交付前逐项过)

| 检查项 | 口径 |
|---|---|
| 盒宽 vs 渲染 | 含标记 desc 的盒宽 = 渲染宽估算(markup 行变短属预期) |
| overlay vs measure | 同一估算函数(含编辑态);`overlays.tsx:77-85` 纪律 |
| 三主题 | classic / sticker / glass 下 strong / code 可辨(附对比截图) |
| LOD / 缩放 | desc 随 k;标题 tspan 随 SVG 变换;k=0.65 / 0.35 档位正常 |
| 存量文本 | 纯文本 zero-diff;含标记文本列观察清单(清单外误伤 = 缺陷) |
| 性能 | `mapview-pan-memo` + `desc-perf` 全绿 |
| 锚点 / 脚本 | `data-desc-text` 等锚保留;`tools/verify-release-123.mjs` 涉及处核对 |

## 5. 分期与工单切分(拍板后直接开工)

**P1 — 摘要区行内富文本(主交付)**
- 范围:`InlineRichText`(strong / code / link 单实现)+ DescBlock 显示态接线 + 宽度估算同步 + 单测。
- 触及:`chrome/InlineRichText.tsx`(新)、`chrome/DescBlock.tsx`、`index.ts` 导出、`tests/desc-block.test.tsx`、`tests/text-links-render.test.tsx` 配套扩展。
- 验收:kitchen-sink 单测(未闭合 / URL 策略 / 转义 / 三态回归)+ 人工视觉(三主题、缩放、滚动、成框行)+ lint / budget 逐数持平。
- 规模:**≈ 1–1.5 天(S~M)**。

**P1.5 — 消费面核验(可并入 P1)**
- 范围:note 序列 / note_text / GrowthComment 两面逐一视觉核对;异常面个别处理。
- 规模:≈ 0.5 天。

**P2 — 标题行内富文本**
- 范围:NodeG tspan(strong / code / link 样式)+ 渲染单测 + pan-memo 回归。
- 验收:三档字号下样式可辨;折行边界降级符合预期;性能回归达标。
- 规模:**≈ 1–1.5 天(S~M)**。

**P3 — 块级内容(暂缓)**
- 列表 / 引用 / 代码块 = 新的块级度量结构(行高 / 缩进 / 嵌套),风险与成本上一档;待 P1 / P2 使用反馈后评估。规模:L ~ XL。

**收尾**:主题对比稿存档 + verify 脚本补充(可选)+ 开发记录(照 dispatch 惯例)。

## 6. 风险与缓解

| 风险 | 等级 | 缓解 |
|---|---|---|
| 存量文本误渲染(成对 `**` / 反引号) | 低 | 预期特性;先扫描仓库用例;观察清单(§4.4) |
| 宽度估算与真实渲染 1%~5% 偏差 | 低 | 近似系数已有(1.05 / 0.95);padding 吸收;视觉抽查 |
| 中文小字重对比不足(strong 不可辨) | 中 | 实现附两版对比稿(增重 / 增重+提亮)再定 |
| memo 热路径回归(标题) | 中 | pan-memo / desc-perf 双套件卡口 |
| 解析边界差异(标题 vs 摘要) | 低 | 已记录;统一管线列后续收敛项 |
