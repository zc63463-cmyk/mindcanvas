## 1. 归属与范围模型（先解决「一屏重复列出相同资产」）

### 1.1 现状的混乱来源

现状 Tabs 把三个不同维度压在同一排按钮上（`AssetPanel.tsx:73-85`）：

| Tab | 实际维度 | 问题 |
|---|---|---|
| 📁 本地上传 | 来源（`source === 'upload'` 或无 `source`） | 把「浏览器 IDB 资产」与「磁盘 assets/ 资产」混为一类 |
| ⭐ 常用 | 用户标记 | 与来源正交，却是同级 Tab |
| 🎨 内置图标 | 来源（`source === 'builtin'`） | 同上 |
| 全部 | 并集 | 同 id 靠 `byId` 覆盖（`workspaceAssetHost.ts:76-78`），磁盘资产与浏览器同 id 资产互相隐藏；而 `builtin:*` 与静态打包资产又同时出现 → **看起来像重复** |

### 1.2 提案：两个正交维度

```text
维度 1 · 归属（scope，单选，决定"这资产在哪、什么条件下才可用"）
   [ 本工作区 ]  [ 浏览器素材库 ]  [ 内置图标 ]  [ 全部归属 ]

维度 2 · 筛选（chips，可多选，不改数据只改视图）
   ⭐ 已收藏   ·   类型：位图 / 矢量   ·   状态：可用 / 失效 / 仅本次会话

（另有一个独立入口：当前文档使用中，见 §1.4）
```

| 归属 | 内容 | 判定依据 | 可携带性（`AssetPortability`，见 `shared-contracts.md` I-12） |
|---|---|---|---|
| 本工作区 | `<workspace>/assets/` 下的真实文件 | `AssetKey = 'ws:<uuid>::assets/<relPath>'` | `folder-relative`：**把整个文件夹拷走**才可用；只拷文档不带文件夹则断图 |
| 浏览器素材库 | IDB `mindcanvas-assets`（`idbAssetHost.ts:19-20`） | `AssetKey = 'browser:local::assets/<name>'` | `browser-local`：只在这台机器的这个浏览器里；**换浏览器、清站点数据、浏览器在存储压力下清理都会失**。**不自动存在**，必须如实告知 |
| 内置图标 | 打包的 `BUILTIN_ICONS`（`AssetPanel.tsx:88-95`） | `id = builtin:<id>`，自带 `svg` | `self-contained`：随应用，永远可用 |

**归属维度不承诺任何「换机器还在」**：上表的可携带性列是唯一的可携带性口径。界面文案禁止把「写入成功」说成「到哪都能用」（对应 `shared-contracts.md` §1.7 的允许/禁止文案表）。

**去重规则**：同一张卡片只出现一次，主键是 `AssetKey`（含归属），**不是** `id`。同名但归属不同的两张图必须并排显示，并各自带归属徽章——这正是「两个工作区都有 `assets/a.png`」的可见化（对应验收 A1）。

每张卡片的最小信息：缩略图 / 名称 / 类型徽章 / **归属徽章** / **可携带性徽章** / 状态徽章 / 大小（若已知）/ 收藏星。

**范围与插入能力不是同一件事（本轮补正）**：面板可以**浏览**浏览器素材库，但能否**插入**取决于当前是否有工作区（`shared-contracts.md` I-10 的插入归一化）。浏览器素材库的定位因此是**来源与暂存区**，不是「可直接引用的素材源」。未挂载工作区时，除小 SVG 内联外不提供插入。

### 1.3 空态与失效态

| 状态 | 表现 |
|---|---|
| 归属为空 | 『这个工作区里还没有图片。上传后会保存到 `<工作区名>/assets/`。』 / 『浏览器素材库里还没有图片（只在此浏览器可用）。』 |
| 筛选无命中 | 『没有匹配「{q}」的素材。』+ 「清除筛选」 |
| 清单加载中 | **骨架占位**（现状无面板级加载态——`current-state.md` §2.3 的缺口），不做空白闪烁 |
| 清单加载失败 | 『读取素材清单失败（{原因}）。』+ 「重试」；已上传但未落盘的会话级项仍可用 |
| 单项失效 | 缩略图占位 + 「失效」徽章 + 禁用插入（接线既有 `isMissing`，`AssetPanel.tsx:41-42`） |
| 仅本次会话可用 | 橙色徽章「仅本次会话」+ 悬停说明『未写入持久存储，刷新后可能消失』 |

### 1.4 「当前文档使用中」是否作为范围

**提案：不作为归属范围，作为独立入口。**

- 理由 1：它的判定依据是**当前文档的引用集合**，与其他三个归属不在同一维度（一个资产可以同时是「本工作区」且在「当前文档使用中」）。
- 理由 2：把它做成第四个 Tab 会让用户以为「使用中的资产只在这一栏」，从而在「本工作区」里找不到已在用的图。
- 落点：面板顶部一行动态 chip『本文档使用中（N）』，点击进入过滤视图，并在卡片上标「已插入」；已插入的项点击行为需明确（见 §3.3）。

### 2.2 名称与类型

- 名称：来自文件名（磁盘）/ `AssetItem.name`（浏览器）。**不做自动改名**（改名详见 §4.4）。
- 类型徽章：`img` / `draw`（`kindOfFileName`，`assetHost.ts:11-14`）+ 扩展名文本。
- 大小：磁盘项由 `listAssetFiles` 扩展返回 `size`（新增字段）；浏览器项由 `AssetRecord.data.byteLength` 提供（**不额外读二进制**）。未知时显示 `—` 且不参与排序（排在最后）。

### 2.3 来源（真实落点）如实呈现

**这是「知道图片保存在哪里」的核心。** 每张卡片必须能回答「它在哪」，而不是只显示「上传成功」。

| 落点（`AssetStore`） | 徽章 | 可携带性徽章 | 悬停/详情说明 |
|---|---|---|---|
| `workspace-assets` | 📁 本工作区 | 📦 随文件夹 | 『保存在 `<工作区名>/assets/<文件名>`。**把整个文件夹**拷走仍可用；只拷文档不带文件夹会显示为缺失』 |
| `browser-idb` | 💾 浏览器 | 🔒 仅此浏览器 | 『保存在此浏览器的本地素材库。换浏览器、清站点数据、或浏览器在存储压力下清理时都会丢失，文档里的引用会显示为失效』 |
| `builtin` | 🎨 内置 | ✈ 自包含 | 『应用自带的矢量图标，任何环境都可用』 |
| 会话级（无 store） | ⚠ 仅本次会话 | — | 『未能写入持久存储（{原因}）。现在能用，刷新后消失』 |
| 内联（小 SVG） | ✎ 已内联 | ✈ 自包含 | 『已作为文本写入文档，单文件拷走也能显示』——同一张图既有磁盘副本又已内联时，两个落点徽章都显示 |

**禁止的表述（本轮明确）**：任何徽章或悬停文本中不得出现「已保存，换电脑也能用」「单文件即可携带图片」之类的说法。可携带性只由本表的第三列表达。

### 2.4 懒加载与分页：代表性数据集与拟定目标

**声明**：下列目标是**拟定指标，本包未做任何性能测量**，不得对外表述为已达标。测量方法一并给出，交 **P1-B 包**执行（包号见 `acceptance-and-backlog.md` §5）。

| 项 | 代表性数据集 | 拟定目标（待测） | 测量方法 |
|---|---|---|---|
| 首屏渲染 | 500 / 2000 / 5000 项 三种规模，混合：≥1MB 位图 5%、16KB 上下 SVG 各 10%、其余小位图 | 首屏 DOM 节点 ≤ 200；首帧可见区外不调用 `resolve` | jsdom 计数 + 真浏览器 Performance 面板 |
| 缩略图请求 | 同上 | 首次加载的图片请求数 ≤ 视口容量 + 1 行缓冲 | 真浏览器 Network 面板计数 |
| 清单加载 | 同上 | 不清空面板、可交互；IDB 分批游标读取，**不再一次 `getAll` 全部二进制** | `idb-asset-host.test.ts` 同族夹具 + 真浏览器计时 |
| 内存 | 2000 项且全部预览过 | objectURL 数量 = 可见窗口 + 缓存上限（见 §6.3）；断开工作区后归零 | 真浏览器内存快照 |

实现路径（分层，可分阶段交付）：

1. **清单元数据与二进制分离**：`listAssets` 只返回元数据（`AssetRecord` 去掉 `data`，用游标分批）；缩略图按需 `get(id)` 取二进制。
2. **网格窗口化**：与列表共用窗口计算（`AssetPanel.tsx:185-199`），或按页加载（每页 60 项 + 「加载更多」）。**推荐窗口化**，与列表口径一致，且不引入分页状态机。
3. **缩略图缓存**：宿主侧 LRU（上限例如 200 个 objectURL），超出即 revoke 最久未用（见 §6.3）。

## 3. 使用：插入、反馈、撤销

### 3.1 三种语义的适用位置（导图）

| 语义 | 落点 | 现状锚点 | 适用条件 | 成功反馈 |
|---|---|---|---|---|
| `icon` 节点图标 | `note.icon`，值为 `data:` URL（小 SVG）或 `kind:id` | `SidePanels.tsx:128-129`；`SidePanels.tsx:39-41` | 建议提示「图标适合小尺寸矢量」；位图可插但视觉上会被压缩 | **现状无反馈** → 新增：节点轻微高亮闪一次 + 面板底部一行『已设为「<节点文本>」的图标』，面板不关闭 |
| `media` 节点插图 | `note.media` | `SidePanels.tsx:130` | 位图/大 SVG 的主用途 | 同上 |
| `child` 子分支 | `controller.addEntityChild` → `@img/@draw` 实体节点 | `SidePanels.tsx:131-134` | 需要资产作为独立节点参与布局/连线 | **已有**：选中新节点 + 视口平移（`MindmapStage.tsx:2372-2375`） |

- 目标节点：现状 `controller.selectedId ?? controller.root.id`（`SidePanels.tsx:129`）。提案：面板顶部显式显示『插入到：<节点文本 或 根节点>』；未选中时写明『将插入到根节点』。**不新增"必须先选中"的硬门槛**（会打断既有流程）。
- 语义顺序与文案：沿用 `ASSET_ACTION_ORDER` / `ASSET_ACTION_LABEL`（`AssetPanel.tsx:24-35`）。
- 插入前的失效拦截：接线 `isMissing`（R-11）→ 失效项禁用插入并在卡片上说明原因。

### 3.2 画布拖放的落点语义（接线缺口）

**现状**：`MapView.onAssetDrop` 与 `dropSensing` 的 icon/media/child/free 四语义与预览浮层**已实现**（`MapView.tsx:274-280,1844-1846`；`dropSensing.ts:73-138`），但产品只接了 `onAssetFiles`（`MindmapStage.tsx:1834`），落点语义不可达（R-12）。

**提案**：接上 `onAssetDrop`，映射关系：

| 落点 | 语义 | 结果 |
|---|---|---|
| 节点中心带 | `icon` | 设为该节点图标 |
| 节点上下带 | `media` | 设为该节点插图 |
| 节点右侧 | `child` | 新增子实体节点 |
| 空白 | `free` | 新增实体节点（**现状无此能力**：`addEntityChild` 只接父节点 → 需要在自由位置新增；P1-B 切片） |

首期若 `free` 成本高，可先只接前三种 + 空白处回退到「插入到选中节点」，并**在提示中写明**（不静默改变语义）。但不得让拖放语义与面板语义不一致到用户无法预测。

### 3.3 已插入的项如何呈现与再次点击

- 卡片在「本文档使用中」视图中标「已插入（N 处）」；`N` 来自当前文档引用计数（纯客户端计算，无需扫描）。
- 再次点击已插入项：**默认仍执行当前语义**（幂等式覆盖，icon/media 是覆盖语义；child 是新增语义并在提示中说明「已新增第 N 个引用」）。**不弹二次确认**，因为模型层可 Ctrl+Z 撤销。

### 3.4 撤销边界（必须如实）

| 动作 | 能否撤销 | 说明 |
|---|---|---|
| 插入 icon / media / child | **能**（模型层 Ctrl+Z） | 经 `EditorController` 的 `apply`/patch 合并进 OpHistory（`controller.ts:250-254,296-301`） |
| 替换已插入的 icon/media | **能**（撤销回上一个引用值） | |
| 删除节点上的引用（移除引用） | **能** | |
| 从图库删除记录 / 删除磁盘资产文件 | **不能** | 模型撤销无法恢复外部文件。删除前必须让用户明白这一点（§4.5 文案） |
| 断图后重新定位 | **不能**"撤销回断图" | 绑定是索引层动作，不进模型历史 |

## 4. 同名、归属与生命周期

### 4.1 同名策略（不静默覆盖）

**现状**：磁盘 `getFileHandle(name, {create:true})` 直接覆盖（`directoryHost.ts:379-386`）；IDB `put(record, id)` 直接覆盖（`idbAssetHost.ts:147`）；Demo 同理（`assetHost.ts:92-96`）。三处都是**静默替换**（R-09）。

**提案**：上传时先探测同名（磁盘：`hasAsset` + 读回元数据；浏览器：清单查同 id），命中则暂停并让用户三选：

```text
① 同名冲突（同名、内容不同）
┌──────────────────────────────────────────────────┐
│ 「diagram.png」已存在于 📁 本工作区。               │
│   现有：assets/diagram.png（240 KB，08-19 加入）    │
│   新文件：diagram.png（310 KB）                    │
│   ⚠ 有 2 处引用正在使用现有文件：                    │
│      • 架构.mm.md（@img 1 处、节点插图 1 处）        │
│   选择：                                          │
│   [ 保留两份 ]  新文件存为 diagram 2.png，            │
│                 现有文件与既有引用完全不变            │
│   [ 显式替换 ]  覆盖现有文件；上述引用将显示新内容      │
│   [ 取消 ]      不写入任何文件                       │
└──────────────────────────────────────────────────┘
```

规则：

| 规则 | 内容 |
|---|---|
| **首期不做去重（推荐最小方案）** | 同名一律走三选。这样「绝不静默替换旧内容」与「绝不漏上传」两条同时成立，实现也最小（`shared-contracts.md` §4.5.2） |
| 默认焦点 | `保留两份`（保住用户新内容且不动旧文件）；`取消` 为第二选择；`显式替换` 不得作为默认 |
| 「替换」的影响范围 | 必须列出**已知**引用处数；若引用范围未知（§4.6），文案改为『还有多少处引用无法确认』并强烈提示 |
| `size` + `lastModified` 的用途 | **只能做预筛选**（用于文案显示「可能相同」）。**不得**据此跳过写入或跳过冲突流程 |
| 同名 + 同内容（可证明） | 仅当**本会话内已读过旧文件字节并与新字节逐字节相同**（或同一次会话内可靠的内容摘要一致）→ 提示『该图片已存在，未重复写入』。**不得**用 `size`+`mtime` 冒充该比对 |
| 同名 + 不同内容（含同名同大小同时间戳不同字节） | 走三选；**默认焦点 `保留两份`**。反例与正确结果见 `../2026-09-19-file-assets-contract-close/counterexamples.md` CE-03 |
| 仅大小写不同（`A.png` vs `a.png`） | 与文件管理同规：大小写不敏感平台上视为同名，走三选；文案里说明这一点 |
| 覆盖后既有引用 | 「替换」语义下，引用不变、内容变——这是用户显式选择的结果，不需改写文档 |
| 作用域 | 冲突检测**只在当前归属内**做。不同归属的同名资产不冲突（各自独立，见 §1.2） |
| 冲突检测失败 | 探测同名本身失败（权限/IDB 不可用）→ **按「已存在」处理**（走三选），宁可多问一次，不可静默覆盖 |

### 4.2 四个容易混淆的「删除」——必须分开设计

这是任务书 §3 的核心问题：「谁拥有资产？」「移除图片 / 删除文件 / 移除收藏 / 图库记录分别是什么？」

| 操作 | 作用对象 | 现状 | 提案措辞 | 影响 | 可恢复 |
|---|---|---|---|---|---|
| **移除节点引用** | 文档模型（`note.icon`/`note.media` 清空，或删除 `@img/@draw` 子节点） | 已有（模型编辑/删除键） | 『移除引用』 | 只改当前文档；磁盘/库里的图不动 | 能（Ctrl+Z） |
| **取消收藏** | 用户标记（`mindcanvas.assets.fav`，`AssetPanel.tsx:71`） | 已有 | 『取消收藏』 | 只改标记 | 能（再点一次） |
| **从图库清单移除记录** | **不删文件**，只从「我的素材」视图隐藏 | **无入口** | 『从素材库隐藏』（悬停说明：不会删除文件，可用「显示已隐藏」找回） | 文档里的引用**不受影响**，图片仍能显示 | 能（显示已隐藏 → 恢复） |
| **删除实际资产文件** | 磁盘 `assets/<name>` 或 IDB 记录 | **无入口**（`AssetHost` 无删除方法，`assetHost.ts:40-52`） | 『删除图片文件（不可撤销）』 | 所有引用它的文档都会断图 | **不能**（无回收站；见 §4.5） |

四者的入口位置必须不同（引用在节点上 / 收藏在卡片星标 / 隐藏在筛选 / 删除在详情页的危险区），避免误触。

### 4.3 上传结果的三种状态（不把"显示成功"当"保存成功"）

**现状**：IDB 写失败被 catch 后仍返回同一个 `AssetItem`（`idbAssetHost.ts:146-150`），上层无 try/catch（`MindmapStage.tsx:888-892`）→ **无法区分**（R-08）。

**提案**：`uploadAssetDetailed` 返回三态 + 一个正交的可携带性（`shared-contracts.md` §4.5.1、I-12），UI 分别呈现：

```text
① 本次写入成功 · 落工作区磁盘（store='workspace-assets'，portability='folder-relative'）
   ✅ 已保存到 本工作区/assets/diagram.png
      把整个文件夹拷走仍可用（只拷文档不带文件夹会显示为缺失）。
                                                          [插入到当前节点] [知道了]

② 本次写入成功 · 落浏览器素材库（store='browser-idb'，portability='browser-local'）
   ✅ 已保存到浏览器素材库（这台机器、这个浏览器）
      ⚠ 换浏览器、清理浏览器数据、或浏览器在存储压力下清理时都会丢失；
        文档里指向它的引用会显示为缺失。跨机器使用时请把它保存到工作区。
                                                          [插入到当前节点] [知道了]

③ 仅本次会话可用（无 store）
   ⚠ 图片已可用，但**没有写入持久存储**（原因：本地存储不可用 / 写入被拒）。
      刷新后这条记录会消失；文档里会显示为缺失。
                                                          [重试写入] [取消]
   （首期不提供「仍然插入」：按 I-10，写进文档的引用必须重开可解析）

④ 失败
   ❌ 上传失败：{原因}
   [重试]  [改存到浏览器素材库]（当原因是工作区不可写时提供）
```

**关键纪律（本轮收紧）**：

- 只有「本次写入成功」才允许文案里出现「已保存」；但它**只说明这次写入成功**，不说明可携带。
- `browser-idb` 的成功提示必须同时给出失效条件（浏览器清理/换机器），不得出现「已保存，换电脑也能用」。
- `session-only` 必须显式说「没有写入持久存储」且**不提供插入入口**（对应验收 A3）。
- 文案不得把「写入浏览器素材库成功」读成「文档已可携带」。

### 4.4 资产改名（新增，低优先）

- 磁盘：改名 = 复制 + 删除 + **改写所有已知引用**；风险高。
- 提案：**首期不做改名**。理由：改名会牵动磁盘文件、所有引用、以及无法枚举的外部引用（Obsidian、其他编辑器）。替代路径：用「另存为副本 + 重新插入」；或用系统文件管理器改名后走「断图修复」（§4.7）。
- 若后续要做：必须先完成「引用扫描」与「改写前备份」，且只在 `full-scan complete` 时允许。

### 4.5 删除实际资产文件的流程

```text
删除前必须完成三件事：
  ① 引用扫描（§4.6），得到 coverage 与命中列表
  ② 文案分级：
     - coverage = full-scan && complete && matches 为空
         『已确认没有文档引用这张图片。删除后不可撤销。』
     - matches 非空
         『有 N 处引用正在使用：<文档名>(x处)…。删除后这些引用会显示为失效，且不可撤销。』
     - coverage < full-scan
         『无法确认是否还有其他文档引用（引用范围未知：当前只检查了 <范围>）。
           删除后不可撤销。』
  ③ 恢复路径说明：
     『本应用没有回收站，删除后无法在应用内恢复。若需要保留，请先用系统文件管理器
       把 <工作区>/assets/<文件名> 复制到别处。』
```

- **首期不做自动垃圾回收**（`shared-contracts.md` I-7）。任何「清理未引用资产」的批量入口都不在首期范围内。
- 删除成功后：清单移除 → 所有引用变为 `unresolved('missing')` → 渲染断图占位 → 面板失效徽章。**不自动移除文档里的引用**（引用是文档事实，删不删由用户决定）。

### 4.6 引用范围与「未知」

| coverage | 何时得到 | UI 措辞 |
|---|---|---|
| `current-doc` | 打开文档后立刻可得（现有 `assetDiagnostics` 的同类计算，`assetDiagnostics.ts:15-30`） | 『已检查当前文档』 |
| `open-docs` | 本项目同时只有一篇打开文档，实际等价于 `current-doc`；保留该字面量以对齐既有表述 | 『已检查当前打开的文档』 |
| `known-docs` | 索引中的文档有 `source`/可读 | 『已检查 N 篇已知文档』 |
| `full-scan` + `complete` | 遍历作用域内全部 `.mm.md`/`.md` 成功，无目录不可读 | 『已检查全部 M 篇文档』 |
| `full-scan` + `!complete` | 遍历中遇到不可读目录/文件 | 『已检查 M 篇，但有 K 处无法读取』 |
| `unknown` | 未扫描 / 扫描中断 / 作用域不可遍历 / 只读外部程序无法枚举 | 『无法确认是否还有其他文档引用』 |

**枚举纪律**：上表六个行对应 `shared-contracts.md` §1.6 的**五个字面量**（`full-scan` 因 `complete` 取值分两行）。代码、文档、验收一律只使用这五个字面量，不得出现同义口语值。
| `unknown` | 未扫描 / 作用域不可遍历 / 只读外部程序 | 『无法确认是否还有其他文档引用』 |

**硬规则**：`coverage !== full-scan || !complete` → 不得显示「无引用」（I-6）。工作区未挂载时删除浏览器资产，只能给 `current-doc` 或 `unknown`。

完整扫描的成本：一次作用域遍历 + 每篇文档的引用抽取（复用 `assetRef.ts:20-43` 的纯函数）。**只在用户点「完整检查引用」时执行**，不后台常驻；结果不持久化。

### 4.7 断图与重新定位

```text
断图的原因，必须区分文案（对应 shared-contracts.md §3.4 的 AssetResolution）：
  ① 未打开工作区（no-scope）
     → 『这份文档的图片保存在它的工作区 assets/ 里，请先打开对应文件夹』
       ← 这不是「丢失」，用户不需要重新定位；不得引导用户去选文件
  ② 工作区里没有这个文件（missing）
     → 『<工作区名>/assets/<文件名> 不在了』+ [重新定位]（下述流程）
  ③ 属于另一个工作区（wrong-scope）
     → 『这张图片属于工作区「<名>」，当前工作区是「<名>」』
  ④ 外部引用（external，http(s):/../ 等）
     → 『外部引用，不纳入图库管理；本应用不会改写它』
  ⑤ 当前环境无法读取（unavailable）
     → 『当前环境无法读取素材库』
```

重新定位动作（详情页 + 断图占位上的入口）：

1. 让用户选文件；
2. 校验类型为图片；
3. 询问落点（当工作区已挂载）：**『保存到本工作区 assets/』**（推荐；这是唯一能让引用重开可解析的落点）。**不提供「只在本次会话使用」**——按 I-10，写进文档的引用必须重开可解析；
4. 若选了「保存到 assets/」，检查同名 → 走 §4.1（默认「保留两份」）；
5. 成功后更新清单并**重新解析**（触发一次 `resolve` 失效，让画布上的断图恢复）；
6. **不改文档**：引用字符串不变，因此不需要编辑文档，也不进入模型历史。若原引用 id 与新文件的相对路径不同（例如原名被占用而分配了新名），则必须**改写文档中的该引用**（进入模型历史，可撤销）——这是唯一需要改文档的情形，且必须在确认文案中说明。

**撤销边界**：清单层面的重新定位不可撤销；因它不改文档，最坏后果只是「清单多了一项」。第 6 条的引用改写可用 Ctrl+Z 撤销。

**撤销边界**：重新定位不可撤销；但因为它不改文档，最坏后果只是「清单多了一项」。

### 4.8 文档操作与资产的关系（共享 / 复制 / 重新绑定）

| 文档操作 | 资产行为 | 理由与提示 |
|---|---|---|
| 插入（当前文档，本轮新增归一化） | **归一化到当前工作区**：字节落 `<workspace>/assets/`，引用 `assets/<relPath>` | 见 §4.9；这是保证「插入→保存→重开」一致的前提（`shared-contracts.md` I-10） |
| 另存为（新建目的地） | **共享**（引用字符串不变，指向同一 `assets/`） | 磁盘资产相对**工作区根**（I-4），另存到的位置即使不同目录也能解析；提示一句『新文件与原文件共用同一批图片』 |
| 复制文档（同工作区） | **共享** | 同上（前提：插入已归一化，文档里不存在指向浏览器素材库的引用） |
| 移动文档（同工作区） | **共享**；引用不改写 | 因为引用相对工作区根，移动文档不影响解析（与直觉相反，必须写明，避免后续误「修复」） |
| 文档搬到另一个工作区（用系统文件管理器） | **不自动携带** | 新工作区的 `assets/` 若没有同名文件 → `unresolved('missing')`；提供「重新定位」入口。**不得**宣称「把文档拷走图片就跟着走」 |
| 文档在**未挂载工作区**时打开 | 引用 `assets/...` → `unresolved('no-scope')` | 文案是「请先打开对应文件夹」，不是「丢失」。若用户在此时插入图片 → 只有小 SVG 内联可行，其余拒绝（I-10） |
| 浏览器素材库里的资产 | 不被任何文档直接引用 | 插入时已归一化到工作区或内联；素材库退为**来源与暂存区** |
| 新建文档 | 无资产 | — |

**本轮补正的关键结论**：初版把「浏览器资产 + 文档拷到别的机器 → 不携带」描述成必然结果。归一化之后，这个失败模式只在「历史文档里已有的旧引用」与「用户只拷文档不带文件夹」两种情形保留——新插入的引用不会产生它。

### 4.9 插入归一化（本轮新增，关闭「内存 scope 与旧引用字符串脱节」）

**问题**：文档里只写得下 `assets/a.png`。当浏览器素材库与当前工作区各有一张 `assets/a.png` 时，「在面板卡片上加 scope 徽章」并不能保证插入与重开解析到同一张图；仅靠内存中的 `AssetKey` 会在重开后失效。

**规则**（`shared-contracts.md` I-10）：

| 当前状态 | 插入行为 | 写进文档的引用 |
|---|---|---|
| 已挂载工作区，所选资产来自磁盘 | 若字节相同（本会话内已完整比对过）→ 复用现有文件；否则若同名不可证明相同 → 分配不冲突名（`<base> 2.<ext>`）写入 | `assets/<文件相对路径>` |
| 已挂载工作区，所选资产来自浏览器素材库 | **先把字节复制到 `<workspace>/assets/`**（同名走 §4.1 三选，默认保留两份），再引用 | `assets/<文件相对路径>` |
| 未挂载工作区，且资产是可净化的小 SVG（≤15KB） | 内联 | `data:image/svg+xml;...` |
| 未挂载工作区，其他情形 | **拒绝插入** | — |
| 内置图标 | icon/media 走内联；**child 也必须内联**（见下） | `data:...` |

**内置图标作为 child 的已知缺口（读码推导，未实跑）**：`SidePanels.tsx:138` 的 child 分支直接写 `{ kind, id }`，不走 `assetValueOf`，因此内置图标会序列化成 `@draw:builtin:<id>`；而 `resolveAsset` 未命中缓存时回落 `baseUrl + id`（`idbAssetHost.ts:127-131`）→ 指向站点根下不存在的路径 → 断图。**设计规定**：child 路径必须与 icon/media 一致地使用内联（或先归一化到工作区），不得直接写 `builtin:` 引用。反例见 `../2026-09-19-file-assets-contract-close/counterexamples.md` CE-05。

**归一化的输入与输出（供实现对齐）**：

```ts
/** apps/canvas 编排；packages/react 提供落盘与去冲突命名的原语 */
type NormalizeResult =
  | { kind: 'normalized'; refId: string; store: 'workspace-assets' | 'builtin'; inline: boolean }
  | { kind: 'refused'; reason: 'no-workspace' | 'unsupported-format' | 'write-failed' };

normalizeForInsert(item: AssetItem, scope: ScopeState): Promise<NormalizeResult>;
```

**与其他动作的关系**：

- 归一化在**插入前**完成，因此「插入」可能触发一次磁盘写入与一次同名冲突对话框；两者都必须有失败与取消路径。
- 归一化产生的磁盘写入同样要计入 `AssetIndexEntry`（`store`、`portability`、`bytes`）。
- 归一化失败 → **不插入**，不改文档（零副作用）。
- 归一化不改变所选资产的清单归属：它在素材库里仍属于原归属（例如 `browser:local`），只是在工作区多了一份副本。UI 需提示『已在「<工作区名>/assets/」保存了一份副本』。

## 6. 缓存与生命周期（objectURL 与异步结果）

### 6.1 问题

现状：`objectUrls` 只有三个 revoke 点（同名替换），没有卸载/断开/切换时的统一释放（R-16）；`WorkspaceAssetHost` 缓存键只有相对路径（R-07）；唯一的迟到防护是组件级 `alive` 标志（`MindmapStage.tsx:908-916`），不校验作用域。

### 6.2 缓存键与代次

```ts
/** 宿主内部：缓存键必须包含作用域 */
type CacheKey = string;  // `${scopeKey}::${relPath}`

/** 所有异步返回都必须带上它被计算时的作用域 */
interface Scoped<T> { scopeKey: string; epoch: number; value: T }
```

- `WorkspaceAssetHost` 与 `IdbAssetHost` 的 `objectUrls` 键改为 `CacheKey`。
- **上传必须在写入前捕获** `{ scopeId, epoch, store }`：`epoch` 在写入过程中可能变化，因此结果必须携带**捕获时**的作用域，而不能读取「当前」作用域。
- `listAssets` / `uploadAssetDetailed` / `resolveAssetState` 的返回都带 `scopeKey` + `epoch`（内部记录，不暴露给渲染层）。
- `apps/canvas` 在回填前调用 `ScopeProvider.isCurrent(scopeKey, epoch)`；不匹配 → **不更新当前清单** + 记一条开发诊断（不打扰用户）。

**丢弃回填 ≠ 撤销写入（本轮明确）**：

> **I-22** `epoch` 变化只允许丢弃 **UI 回填**；写入一旦发生就已经在磁盘/IDB 上留下文件，必须**记账**（`AssetIndexEntry.unconfirmed: true`，属于捕获时的 `scopeId`），下次该作用域挂载时由 `listAssets` 重新发现并清除标记（`shared-contracts.md` §4.5.4）。
>
> 反例：把「切换后丢弃结果」实现成「什么都不做」→ 用户切回原工作区时看到一份自己不知道哪来的文件，或者反过来以为上传失败而重复上传。两者都不是正确行为。

**用户可见文案**（若在切换前已经看到进度提示）：「图片已写入「<原文件夹>/assets/」，但工作区已切换；切回后可在素材库看到。」

### 6.3 释放策略

| 时机 | 动作 |
|---|---|
| 同名替换 | revoke 旧 URL（现状已有，保留） |
| 作用域切换（`pick` / `detach` / 替换目录） | 释放**该作用域的全部** objectURL（按 `CacheKey` 前缀过滤）；不影响其他作用域 |
| 缩略图缓存超上限 | LRU revoke 最久未用（上限建议 200） |
| 组件卸载 | 释放全部；宿主实例若被复用必须提供 `disposeScope(scopeKey?)` |
| 页面卸载 | 浏览器自动回收；不额外处理 |

`resolveAssetState` 在 URL 已被 revoke 后必须能返回 `pending`（重新建/重新读），**不得返回失效的 `blob:` 字符串**。

### 6.4 不把 URL 当身份

重申 `shared-contracts.md` I-3：`objectURL` 永不进入文档、索引主键、收藏键。现状资产收藏键是 `${kind}:${id}`（`AssetPanel.tsx:162,178-179`）——**这是 id 不是 URL，符合要求**，但需要升级为 `AssetKey`（含作用域），否则两个工作区的同名资产会共用一条收藏（与 R-05 同族）。

## 7. 自由画布的能力缺口（单列）

| 能力 | 现状 | 提议 |
|---|---|---|
| 图库面板 | **无**（`packages/react/src/free-canvas/` 零 asset 命中） | 复用 `AssetPanel`（它是纯展示 + 回调，不依赖导图），在自由画布侧提供同样的宿主（`WorkspaceAssetHost(IdbAssetHost(...))`）与 scope |
| 资产插入 | **无** | 自由画布写盘需要落到**同一文档格式**里：`CanvasDoc`（`.mc.canvas.json`）。设计上先把「资产引用」作为自由画布文档的一个受控字段（例如自由节点的 `asset: {kind,id}`），**不改导图格式** |
| 画布拖放 | **无** | 与导图共享落点语义需要自由画布的节点模型支持 icon/media/child；首期只支持「新增自由节点并绑定资产」 |
| 断图诊断 | **无** | 复用 `assetDiagnostics` 纯函数 |
| 资产持久化 | 需要工作区（当前自由画布无工作区入口） | 决策项 D2-D1（见 §10）——**用户已确认首期不纳入** |

**结论（本轮更正）**：自由画布的图库支持**不是 P0/P1 串行链上的一个包**，而是一个**独立的后续设计 + 实现包**（`acceptance-and-backlog.md` §5 的「P1-C 自由画布能力（单列，不在串行链上）」）。

- UD-1 决定的是「自由画布首期不纳入工作区与文件面板」，它**不构成**对任何自由画布资产实施方案（包括「仅会话插图」）的批准。
- 因此本文件只给契约与差距，不设计细节 UI，也不把「无功能但提示不支持」当作能力对齐的证据。
- 启动前必须先有自由画布资产设计（格式、宿主、作用域、断图语义）并单独评审。

## 8. 安全边界（SVG 与远程图）

| 类型 | 加载 | 持久化 | 导出 | 安全 |
|---|---|---|---|---|
| 位图（png/jpg/gif/webp/avif） | `<img src=objectURL>` | 磁盘或 IDB | PNG/SVG 内嵌引用（PNG 导出可能 tainted → 降级 SVG，`useExportActions.ts:71-72`） | 无脚本风险 |
| 大 SVG（>15KB） | `<img src=objectURL>`（**不内联执行**） | 磁盘或 IDB（不存源码文本，`idbAssetHost.ts:143-145`） | 同上；外链时 PNG 导出可能 tainted | 走 `<img>` 而非内联 DOM，脚本不执行 |
| 内联 SVG（≤15KB 单色/多色） | 经 `sanitizeInlineSvg` 净化后内联进 DOM（`svgTint.ts:108`） | 作为文本写入 `note.icon`（`data:` URL） | 自包含，PNG 导出无 tainted 问题 | **净化白名单**是唯一入口：剔除 `<script>`、事件属性、`foreignObject`、`javascript:` 变形、`data:text/html`（既有测试 `svg-tint.test.ts:24-77`） |
| 远程 URL（`@img:https://…`） | 现状：不在清单 → `W-ASSET-MISSING`（`assetDiagnostics.ts:15-30`） | 不持久化 | PNG 导出 tainted → 降级 SVG | 新入口必须沿用同样的净化与「不执行不受信任内容」边界 |

**新增入口的安全要求**（写给后续实现包）：

1. 「重新定位」选中的 SVG 文件**必须**先过 `sanitizeInlineSvg`；净化失败 → 拒绝并说明「这个 SVG 含不被允许的内容」。
2. 「浏览器资产 → 写入磁盘」时不做格式转换（不把 SVG 转 PNG），避免引入新的渲染攻击面。
3. 预览大 SVG 一律走 `<img>` / objectURL，**不得**为预览把 SVG 源码插进 DOM。
4. 远程 URL 引用在 P0/P1 **不新增入口**；当前它们只会显示为缺失，不会被执行。
