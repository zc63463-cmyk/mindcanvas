# MindCanvas 文件管理与图库增强 · 设计候选

任务代号：FILE-ASSETS-DESIGN｜日期：2026-09-19｜状态：**设计候选可复核**（未实施、未提交）

---

## 1. 结论（一段话）

当前实现已经具备文件树、搜索、最近、收藏、目录操作、图库网格与列表、上传四入口、三语义插入、IndexedDB 与磁盘双持久化、断图占位与缺失诊断。**真正缺的不是界面，而是身份与失败语义**：文件被改名/移动后没有身份延续机制，资产没有作用域隔离，"保存成功"与"仅会话可用"在接口层不可区分，文件操作的失败与部分成功没有用户可见通道。

本设计推荐**方案 B：显式作用域 + 稳定索引 + 兼容引用**——身份升级只发生在内存与索引层，**不改 `.mm.md` / `.mc.canvas.json` 语法、不引入数据库服务、不做云同步**；先补可靠性（P0），再补日常工作流（P1），最后做可携带打包（P2）。

## 3. 推荐方案与理由摘要

| 维度 | A 最小修补 | **B 显式作用域 + 索引（推荐）** | C 自包含项目包 |
|---|---|---|---|
| 兼容成本 | 最低 | 中 | 高 |
| 改名/移动识别 | 无 | 完整（血统继承） | 完整（包内） |
| 跨工作区同名隔离 | 部分 | 完整 | 完整 |
| 是否需改文档格式 | 否 | **否**（P0/P1） | 是 |
| 迁移风险 | 无 | 中（幂等可回退） | 高 |
| 是否需外部服务 | 否 | 否 | 否 |

理由：
1. 现有「相对路径引用 + 小 SVG 内联」已提供「文件夹拷走仍离线可读」的能力（`workspaceAssetHost.ts:8-13` 的原始动机），改格式会破坏这项既有价值。
2. 现有编排层（保存会话令牌、离开决策器、宿主注入）已具备承载显式作用域的全部扩展点，B 是在其上做加法。
3. 浏览器**无法**提供 inode 级真实文件身份；B 用「作用域内相对路径做主键 + 血统键做迁移依据 + 显式重新定位」把这一限制变成可解释的 UI 事实，而不是假装能自动识别同名/同一文件。

完整比较与不变量（**I-1…I-22**）见 `shared-contracts.md` §5；其中 I-10…I-22 为本轮契约补正新增（见 `../2026-09-19-file-assets-contract-close/contract-delta.md`）。

**方案 B 在本轮的收窄（必须知道的三条）**：

1. **工作区身份不是任意稳定**：只在「注册表保留期（最多 8 个条目）内且能用 `isSameEntry` 证明同一目录」时保留身份；否则保守降级为会话作用域并要求用户人工关联（`shared-contracts.md` §1.2.7）。
2. **未挂载工作区时，除小 SVG 内联外不能插入图片**：插入必须归一化到当前工作区，否则重开必断图；浏览器素材库退为来源与暂存区（I-10）。
3. **「写入成功」不等于「可携带」**：磁盘写入成功只意味着「随整个文件夹拷走可用」；浏览器素材库写入成功只在「这台机器、这个浏览器」有效（I-12）。

## 6. 决策分层（2026-09-19）

### 6.1 用户已确认（不再询问；**这些决定不代表功能已实施**）

| 编号 | 事项 | 已确认裁决 | 落实位置与边界 |
|---|---|---|---|
| **UD-1** | 自由画布文档是否纳入工作区与文件面板 | **首期不纳入** | `file-management.md` §2.3 / §8.1。**边界**：这一条只决定「不进文件面板」，**不构成**对「自由画布仅会话插图」实施方案的批准——自由画布的资产能力仍未设计（`../2026-09-19-file-assets-contract-close/contract-delta.md` CD-16） |
| **UD-2** | 「最近」是否拆成两项 | **不拆**；保留一个「最近」视图，按 `openedAt` 排序 | `file-management.md` §2.1。**边界**：旧条目没有真实打开时间时，`openedAt` 为 `null`，条目排在末尾并显示「未记录打开时间」；**不得把 mtime 伪装成打开记录**。`savedAt` 只作条目元信息展示 |
| **UD-3** | 是否提供「改为归档」替代永久删除 | **提供**（P1-A 切片） | `file-management.md` §3.6 / §8.1。**边界**：归档**依赖 P0-A 的可靠移动**——移动未落地前不得把归档当作可用补救路径；归档是保留文件的应用操作，不是系统回收站 |
| **UD-4** | 删除资产是否允许在「引用范围未知」时进行 | **允许**，但必须有显式警告 + 不可撤销说明 | `asset-library.md` §4.5 / §10。**边界**：仍然禁止任何自动清理 |
| **UD-5** | 索引层是否向用户暴露 | **不暴露** | 全文用户语言化；`shared-contracts.md` §6.2.1 的「未关联工作区记录」措辞 |
