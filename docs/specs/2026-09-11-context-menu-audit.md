| 项 | 值 |
|---|---|

## 0. 结论摘要（TL;DR）

- **现状**：典型普通节点菜单 **28 项全扁平**——含「升为中心 4 项」「生长方向 4~5 项」「出线长度 5~6 项」三组四向/数值展开（占 15+ 项）；无分区标题、无快捷键提示、无子菜单。
- **增长轨迹**（逐版追加、从未回收）：v1.3 描述 → v1.4 笔记 → v1.5 Section/中心 → v1.6 出线长度 → v1.7 枢纽/连线 → v1.7.1 清除左右。
- **三个问题**：① 扫描成本（28 项平铺，找一项要逐行读）；② **双确认体验不一致**（菜单删除走原生 `confirm()`，环内删除走 v1.8.0 气泡）；③ 原生弹窗质感（`prompt()` 自定义长度——阻塞、不可样式化、部分 webview 受限）。
- **提案**：P0 分区 + 快捷键提示（纯展示，零动作变更）→ P1 弹窗统一（chrome 气泡）→ P2 文案修订 → 定 ② 子环四席。
- **与环的关系**：一级环已覆盖 新建/编辑/删除；菜单的独特价值 = **无快捷键的结构性操作**——这正是子环要收的（§4）。

## 2. 问题清单（证据化）

| # | 问题 | 证据 | 影响 |
|---|---|---|---|
| 2.1 | **28 项无分区** | §1 计数；三组四向/数值展开占 15+ 项 | 扫描成本高；新用户找不到、老用户靠肌肉记忆位置 |
| 2.2 | **双确认体验不一致** | `contextMenuItemsFor` L363 用 `confirm()`；环内删除走 `ConfirmChip`（1.6s 气泡，Enter/Esc） | 同一动作两种交互；原生 confirm 阻塞、不可撤销窗口 |
| 2.3 | **原生 prompt** | L311「出线长度 › 自定义…」`prompt()` | 质感断裂、部分 webview 受限、无法与设计 token 对齐 |
| 2.4 | **两组四向语义易混** | 「升为中心 › 方向」（岛级钉坐标）vs「生长方向 › 方向」（子级生长轴） | 用户难区分两者差别（文案无解释） |
| 2.5 | **无快捷键提示** | 菜单项只有 label，无 hint | Tab/F2/Del/Space 等捷径不可发现（环已承接一部分） |
| 2.6 | **组件能力缺口** | `ContextMenuItem` 仅 `{label,onSelect,danger,disabled}`；`key={item.label}` | 无分区/分隔/hint/子菜单；label 作 key 脆弱（改文案即换 key） |
| 2.7 | **菜单与环的一级功能重复** | 新建/编辑/删除同时存在于环与菜单顶层 | 属合理冗余（可发现性），但置顶顺序应与环对齐以形成一致心智——见 M1 |

## 3. 清理提案

### 3.1 P0 — 菜单分区 + 快捷键提示（推荐先做；纯展示，零动作变更）

- `ContextMenuItem` 增可选 `section?: string`、`hint?: string`；`ContextMenu` 渲染**分区标题**（小号 muted 文本）与**右侧快捷键 hint**（kbd 样式）；分区之间自动分隔线
- 建议分区与成员（顺序可按 M1 调整）：

| 分区 | 成员 |
|---|---|
| **常用** | 新建子节点 (Tab) / 新建同级节点 (Enter) / 编辑 (F2) / 删除节点 (Del, danger) |
| **内容** | 编辑描述 (Shift+Enter) / 编辑 note笔记 / 改引用… / 在关系图中显示 / 转为纯文本 / 复制中心编号 |
| **结构** | 缩进 (Shift+Tab) / 反缩进 / 折叠展开 (Space) / 连线到… / 标记·取消 Section |
| **生长与连线** | 生长方向 › … / 出线长度 › … / 清除左右（残留时） / 升级·取消出线枢纽 |
| **岛与区域** | 升为中心 › … / 降格 / 显示·隐藏父级连接 / 接为子树（detached） |

- 【拍板 M1】「常用」四件与环一级**对齐置顶**（推荐：一致心智）vs 保持现有顺序（老用户肌肉记忆）——推荐前者，一次换位换长期一致

### 3.2 P1 — 弹窗统一（chrome 气泡；与环共用单一实现）

- 从 `useRadialStage` 的确认气泡抽 `chrome/ConfirmChip.tsx`（危险色 + 确认/取消 + 1.6s 窗口 + Enter/Esc）
  - 菜单「删除节点」：`confirm()` → ConfirmChip【拍板 M2：统一（推荐）/ 保留原生】
- 「出线长度 › 自定义…」：`prompt()` → **数值小气泡**（输入框 + 最小 14 校验 + Enter 确认 / Esc 取消）【拍板 M3】
- 两个动作仍走 `updateNote`/`removeNode`（撤销链不变）

### 3.3 P2 — 文案与语义修订（低风险，逐条可单测）

- 「升为中心」→「升为中心（钉住坐标，可拖放）」；「生长方向」→「生长方向（子树往哪边长）」——消解 2.4
- 「编辑描述」→「编辑描述（盒内）」；「编辑 note笔记」→「编辑笔记（盒下）」【拍板 M4：改名涉及测试断言，可只加副标题不改主名】
- 「清除左右（…）」→「清除左右出线残留（…）」（可选）

### 3.4 明确不做（YAGNI）

- 子菜单 / 多级 hover 展开（② 子环是快捷面；菜单保持「扁平 + 分区」）
- 菜单项排序自定义 / 隐藏 / 图标系统
- 文件管理器菜单重构（独立范围）

## 4. 与 ② 二级环的接口（B2 定向）

子环四席筛选口径：**无快捷键（或快捷键生僻） + 一次性动作 + 高频**。候选：

| 席位 | 候选 | 依据 | 备选 |
|---|---|---|---|
| 上 | **编辑描述** | 高频内容入口；一级环未覆盖 | 连线到…（仅关系模式 ❌） |
| 右 | **编辑笔记**（note） | 高频内容入口 | 折叠展开（有 Space ❌） |
| 下 | **升级 / 取消出线枢纽**（动态文案） | 布局调整核心开关（无快捷键） | 升为中心（四向复杂，留菜单） |
| 左 | **打开完整右键菜单**（渐进披露兜底） | 保底可达一切 | — |

- 动态可用性：子环内容 = 静态表 ∩ 条件过滤（如「复制中心编号」仅中心节点时可用）——实现为纯函数 `submenuItemsFor(controller, id)`，**单一动作源**（与 `contextMenuItemsFor` 同文件、同动作闭包）
- 【拍板 B2】四席终版（默认按上表推荐）

3. **P2**（文案）：单测锁定新文案
4. **② 开工**：按 §4 定版四席出 dispatch 计划（writing-plans）
