# Agent ↔ mindcanvas 体裁技能包设计（路线 A）

> 日期：2026-09-17  
> 状态：**已拍板；D2✅ D3✅；可选 D4/D5**  
> 背景：用户需要外置 Agent（Cursor / Codex 等）① **深度读懂**已有导图；② 按自然语言画出 **内容合适、结构清晰** 的架构/流程等图。  
> 约束：产品 **不做** 画布内嵌 Agent / 操作 MCP / 30 tools（对齐 `docs/2026-09-05-project-graph-调研与减法设计.md` §5）。

## 0. 一句话

**两份契约、一个外置 Skill：**「怎么读懂 `.mm.md`」+「自然语言体裁 → mindcanvas 模式怎么画」；Agent 只通过读写文件交互，质量靠体裁路由与结构闸，不靠内嵌模型或像素生图。

---

## 1. 问题与目标

### 1.1 两种交互（仅此）

| 方向 | 用户侧 | Agent 侧成功标准 |
|---|---|---|
| **读** | 已有图（`.mm.md` 等） | 能复述：岛清单、主路径一句话、跨岛关系（自由边），不把父子当因果 |
| **画** | NL：「画某项目架构图/流程图…」 | 产出可打开的合法 `.mm.md`，体裁匹配、节点预算内、结构可扫读 |

### 1.2 非目标

- 画布内 AI 面板、function calling、画布操作 MCP  
- Archify 式独立 JSON IR + 自有渲染器（本路线用 mindcanvas 原语表达）  
- 以 PNG/SVG 生图作为事实源（可读性对 Agent 差）  
- B 线 Sidecar / Forgejo 写回（正交；本设计不依赖）

### 1.3 成功标准

1. 外置 Agent 仅凭 Skill + 打开的 `.mm.md`，能复述岛与主路径。  
2. 「画某某架构/流程」→ 用户打开文件后结构符合体裁表，**无需先拖布局**也能读。  
3. 零画布内 Agent 代码；不新增操作类 MCP。

## 3. 读图契约（深度理解）

权威句法见 `docs/specs/2026-09-02-mm-md-protocol.md`。下列为 **AI 语义读取顺序**（跳读易误判拓扑）。

### 3.1 必读顺序

1. **H1 根 + 标题/列表树** — 父子 = 结构从属，不是因果/依赖。  
2. **根 note：`centers` / `cid` / `sections`** — 多岛与分区。  
3. **`root.note.edges`（或文档级 edges 块）** — 跨岛 / 非父子语义边；自由边 **唯一活跃写入面**（ADR-0008）。  
4. **实体与资源**：`@kind:id`、`@img:`、`@draw:`。  
5. **可读时可忽略**：`pos` / `lens` / `beamAt` 等纯视觉微调（理解「图在讲什么」时不依赖）。

### 3.2 理解规则

- 父子边 ≠ 因果/阻塞/调用；跨主题关系 **必须** 看 `edges`。  
- 多中心 = 多岛；岛内树是局部大纲；岛间靠自由边或既有 parent/island 语义，禁止脑补未写出的边。  
- 复述模板（读完应能填空）：  
  - **主路径一句话**：…  
  - **岛清单**：…  
  - **跨岛关系**：…（无则写「无文档级自由边」）

### 3.3 传出上下文（产品可选 G9）

用户若只需局部：复制选中子树 Markdown，避免整文件灌进上下文。Skill 应优先消费「用户粘贴的子树」+ 必要时再读全文 centers/edges。

## 4. 体裁 → mindcanvas 模式（画图路由）

**口诀**：先定体裁 → 再定「几座岛」→ 再定「岛内树还是岛间边」→ 最后写标题文案。

| 用户意图 | 首选载体 | 结构模式 | 禁用 / 慎用 |
|---|---|---|---|
| 架构 / 系统组成 | `.mm.md` | 每服务/层一个 **center**；依赖走 **自由边**；信任边界用 section 或短标注 | 深嵌套硬塞成一棵巨树 |
| 流程图 / 步骤 | `.mm.md` | 单主干深树（建议右向或下向生长）；分支用兄弟；异常用 note 或次级边 | 无必要多中心 |
| 因果 / 依赖网 | `.mm.md`（或先材料→再写） | 入度≈0 作中心；树骨架 + 跨支自由边（对齐 `graphJsonToMindmap` 策略） | 把环硬写成父子 |
| 对比 / 方案 | `.mm.md` | 2–4 并列中心，同构子树 | 强行一条时间线 |
| 组织 / 汇报 | `.mm.md` | 单根分层；H2≈一级部门 | 自由边过多 |
| 自由草图 / 空间拼贴 | `.mc.canvas.json` | 自由画布；需要时挂 `@img` | 硬用导图表达无层级拼贴 |
| 已有示意图 | `.mm.md` | `@img:` + **并列文字结构摘要**（供 Agent 可读） | 仅图无字 |

### 4.1 与现有能力的接缝

| 能力 | 画图时怎么用 |
|---|---|
| Centers / forest | 架构、对比的默认岛模型 |
| `root.note.edges` | 跨岛依赖、调用、数据流 |
| Sections | 分区/边界标签，不代替中心 |
| AssetHost / `@img` | 外部示意图；须配文字骨架 |
| `graphJsonToMindmap` | 因果图已有 graph.json 时可适配；**画布壳暂无一键打开 UI** 时，Skill 仍应直接写 `.mm.md` 等价结构 |
| 自由画布 | 仅上表「空间拼贴」行 |

## 5. 写图流程（NL → 文件）

```
用户自然语言
  → 澄清范围（系统边界 / 深度 / 受众）——最多 1 轮；缺省「可读优先、节点宁少」
  → 选体裁行（§4）
  → 起草大纲（落在 §6 预算内）
  → 写成合法 .mm.md（协议 canonical；缩进一致）
  → 跑自检清单（§6）
  → 交给用户用 mindcanvas 打开
  → 不代改 pos / lens / beamAt（布局交给产品默认）
```

### 5.1 内容合适

- 标题短、可扫描；细节进 note / `one_liner`，不堆长段进标题。  
- 命名具体（服务名、步骤名）；禁止「节点1 / 临时 / asdf」。  
- 受众默认：同事可读的一页图，不是数据库 dump。

### 5.2 结构清晰

- 一岛一主题。  
- 主路径可一句话复述。  
- 跨主题关系不造假父子；走自由边或拆岛。

## 6. 质量闸（Agent 自检）

失败时 **改结构**，不靠堆节点「显得丰满」。

| 闸 | 默认阈值（可按体裁微调） |
|---|---|
| 节点数 | 架构 8–20；流程 6–15；对比每侧 ≤8 |
| 深度 | ≤4（流程可到 5） |
| 中心数 | 架构 3–8；流程通常 1；对比 2–4 |
| 自由边 | 仅有跨岛/非树语义时写；禁止装饰边 |
| 协议 | 写出后须可被现行 parse 无损往返；不手搓非法 note YAML |
| 读回 | Agent 自己按 §3 复述一遍，填不出主路径则重写 |

## 7. 外置 Skill 形态（实现指引，非本文件代码）

Skill 建议包含：

1. **何时触发**：用户要读 mindcanvas 图 / 要画架构·流程·对比等。  
2. **强制读取**：本设计 §3–§6 + 协议规格路径。  
3. **输出**：工作区路径下的 `.mm.md`（或明确要求的 `.mc.canvas.json`）；简短说明体裁选择理由（给用户，非写进图）。  
4. **禁止**：声称已「调用画布 API」；禁止只交 PNG 当交付物；禁止发明未在协议中的顶层字段。

安装面：本仓库 `.cursor/skills/mindcanvas-diagram/`（Cursor 项目 Skill）；亦可复制到用户全局 skills。与 mindcanvas app 进程无关。

## 9. 风险与纪律

| 风险 | 缓解 |
|---|---|
| Agent 把自由图画成深树 | Skill 强制 §4 路由；架构默认多中心 |
| Agent 读写破坏往返 | 契约强调协议；自检「须可 parse」 |
| 与 B 线/MCP 混淆 | 文档写明：文件通道 ≠ Sidecar ≠ graph-engine 画图 |
| 阈值过严扼杀复杂系统 | 允许用户 NL 声明「深度优先 / 节点上限放宽」 |
