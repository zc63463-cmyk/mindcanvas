> 审计基线：136 commits / 287 files / **571 测试全绿**（kernel 282 + react 289）/ typecheck+build 0 错误

| # | 事实 | 证据 |
|---|---|---|
| 1 | **引擎超额完成**：K0-K5 + 8 轮涌现批次（图库/多文档/关系图/导出/触控/Canvas L3/实体全链路），测试 136→571 | git log 136 commits；T8 降级阶梯 L0-L4 全落地 |

## 二、核心判断（本轮规划的立论）

**引擎侧边际收益已趋零，价值侧约束未被触碰。** 过去两天 8 个批次全部是引擎/产品深化（M 线），而项目的差异化主张——Terraform for ideas——仍停在工具链就绪态。同时出现了一个新结构缺口：

> **产品壳缺口**：apps/canvas 仍是「demo 形态」（gateway 单文档硬编码入口 + 玻璃浮层堆叠），不具备「打开就用」的应用形态。B4 的「自用 1 周」验证因此无法真正发生——没有壳，就没有日常使用。

因此下一阶段的主线不是「再做一个功能」，而是三步走：**清债 → 产品壳 → 自用验证 → 带真实需求回归 B 线**。

## 三、三步走 + 插入项

### 第 2 步 · 自用验证周 F（7 天，零开发）

- 产出：真实缺陷清单（按「阻碍我完成任务」排序）→ 这就是下一轮功能规划的**唯一事实源**

### 第 3 步 · B 线回归（带真实输入）

- F 周的真实画布作为 B0 的**第四张输入**（替代部分 demo 画布）→ 提议集质量在真实数据上复核

### 插入项（按缺陷清单驱动，不预排）

Canvas 模式补全（hover/图片/多行文本/折叠命中）、场景 diff 增量重绘、移动端触控深化、E1 PomodoroXI 接入（门槛：B3）。

## 四、明确不做（本阶段）

- ❌ I3 公网部署（等 B 线稳定自用后）
- ❌ 内核契约变更（ADR-0004 冻结纪律不变）
