# F 自用验证周 · 执行手册（Deep Guide）

> 日期：2026-08-30 · 配套：`2026-08-30-next-phase-roadmap.md` 第 2 步
> 定位：**零开发**。7 天里你不写一行 mindcanvas 代码——你用它管理真实工作，把摩擦记下来。
> 这份手册解决一个反直觉问题：工程师的肌肉记忆是「发现问题就修」，本周恰恰相反。

## 〇、为什么是 F 周（一句话）

引擎 573 测试全绿、8 轮批次、L0-L4 降级阶梯——但我们**没有任何一天真实使用过它**。
B4 的「自用 1 周」是价值验证的最后一环；没有它，后面所有功能都是臆测。

## 一、第 0 天准备（30 分钟，一次性）

### 1. 建工作区（10 分钟）

在 mindcanvas 仓库内建 `docs/work/`（或你习惯的笔记目录），画布放在那里，`文件 → 最近` 即可达。

### 2. 建三张真实画布（15 分钟，模板如下）

**a) `docs/work/pomodoroxi-plan.mm.md`**（PomodoroXI 迁移——你有现成 backlog：20 功能 + 12 stub）：

```markdown
# PomodoroXI 迁移

## Stage 4 前端
- 引擎 API 对接前端视图

## P0 缺陷修复
<!--
one_liner: move_note 不移动文件
status: open
-->
- @issue:<真实编号或暂留文本>

## P1 重构
- engine.py 732 行拆 3 文件
```

**b) `docs/work/skill-hub-map.mm.md`**（MySkill-Hub 技能路线）：把你 92 个技能按「成熟/开发中/想法」三组铺开，想清楚哪个技能给哪个画布引用。

**c) `docs/work/mindcanvas-dev.mm.md`**（本项目自举）：把 post-v1-roadmap 的 B/M/E/I 四线画进去——B 线的节点就是将来 B1-B4 的工单（F 周结束直接当 B0 第四输入）。

### 3. I1 三步（10 分钟，我可以代劳的部分见下）

1. 启动 Forgejo（`localhost:3001` 当前离线）
2. 建空仓 `mindcanvas`（或发我 API token 由我建）
3. 把 `地址 + token` 给我 → 我完成 remote + push 136+ commits

## 二、每日循环（≤20 分钟）

| 时段 | 动作 | 提示 |
|---|---|---|
| **早 5min** | 打开当天主画布 → 扫状态徽章 → 选今天推进的 1-3 个节点 | 用 Ctrl+Shift+R 关系图看全貌一次 |
| **中（随发生）** | 产生想法/新任务/新依赖 → 打开画布加节点；与既有实体相关 → `@` 引用 | 节点笔记记 `one_liner/status/next`（这是 B0 实测证明最有效的字段） |
| **晚 10min** | 复盘 → 在 `docs/work/friction-log.md` 追加当天摩擦行（模板见下） | 只记录，不修 |

## 三、摩擦记录（friction-log.md）

### 模板

```markdown
| # | 日期 | 场景 | 我做了什么 | 卡在哪 | 我期望 | 严重度 |
|---|---|---|---|---|---|---|
| 1 | 08-31 | 想给 PomodoroXI 的缺陷节点关联 issue | 双击节点输入 @issue:12 | picker 里没有我的 issue（候选只有演示实体） | 候选应来自我的 Forgejo | major |
```

### 什么算「好的摩擦记录」

- ✅ 具体场景 + 复现步骤 + 期望（可转化为验收标准）
- ❌ 「不好用」「体验差」（无法行动）
- 严重度三档：`blocker`（今天的工作被它挡死）/ `major`（绕过去了但不爽）/ `minor`（有更好方式）

### 本周大概率会遇到的摩擦（预判，供对照）

1. **实体候选没有你的真实数据**（B 线未通）→ 记录「我希望 picker 里出现什么」
2. Canvas 模式（>50K）缺 hover/编辑入口
3. 移动端：面板宽度、编辑浮层在小屏的表现
4. 多文档间切换找文档的方式
5. 快捷键与你的肌肉记忆冲突（Ctrl+Shift+R 等）

## 四、一周后复盘（D-B 决策点，30 分钟）

回答四个问题，写进 `friction-log.md` 顶部：

1. **几天真用了？** ≥4 天 → 日常化成立；≤2 天 → 是什么让你回去用旧工具（这就是壳的真缺口）
2. **天天用的功能是哪三个？** → 它们是产品核心，下轮优先保
3. **从没碰过的功能是哪几个？** → 候选「砍/降级」清单
4. **`.mm.md` 作为事实源够吗？** 有没有想把画布数据导出/推送的场景 → 直接成为 B 线需求输入

### 决策分支

- 日常化成立 + 摩擦 top5 清晰 → **B 线回归**（B1-B4，真实画布做 B0 第四输入，EntityHost/AssetHost 远端接缝直接复用）
- 日常化不成立 → 复盘壳缺口 → S 批二轮（只修 blocker 级）

## 五、红线（本周纪律）

1. **不写 mindcanvas 代码**。发现 bug → 记 friction-log。唯一例外：blocker 级（完全无法完成当天工作）才允许热修，且记录「热修了什么」
2. **不为 F 周新做功能**——F 周本身就是测试
3. 每日记录 ≤15 分钟——超时说明记录格式太重，简化它
4. 画布坏了/卡了本身也是数据：「第 X 天画布让我放弃了」是最有价值的记录
