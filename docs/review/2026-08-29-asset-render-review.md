# 资产节点（@img/@draw）显示效果审查与诊断

> 日期：2026-08-29 · 触发：用户「我感觉存在问题」+ 截图反馈
> **重要声明**：本次审查**无法读取用户截图**（当前模型不支持图像）。因此诊断**完全基于源码审阅与可量化计算**，而非视觉观察。凡源码能证实的（对比度数值、布局常量、渲染层叠顺序）均为硬证据；凡涉及主观视觉感受的，已标注为推断。
> 附带更正：本人在无法读图时曾基于上下文推测过截图细节（如「@img 文字角标与文件名抢空间」「折叠三角在右下角」），经源码核对**这两条推测均不成立**（排版正确、折叠器在右侧垂直居中）——已撤回。

## 一、审查方法

1. 渲染链路代码审读：`NodeG.tsx`（节点渲染）/ `MapView.tsx`（布局与分发）/ `nodeLayout.ts`（尺寸度量）/ `tokens.ts`（主题令牌）
2. 布局常量与高度公式核对
3. 主题对比度计算（glass 主题连线）

## 二、诊断结论（按严重度）

### 🔴 P0-1 · 布局引擎完全不知道资产存在（核心 bug）

**证据**：
```ts
// packages/kernel/src/layout/nodeLayout.ts:92
const h = Math.max(MIN_H, lines.length * LINE_H + 12)   // ← 仅文本行数决定高度

// packages/react/src/render/NodeG.tsx:90-99
<image href={assetHref} x={4} y={4}
       width={b.w - 8} height={bodyH - 8}          // ← bodyH 即上面那个文本高度
       preserveAspectRatio="xMidYMid meet" />
```
`grep -rn "assetH" packages/kernel/src` **零命中**——内核侧无任何资产高度概念。

**后果**：
- 单行实体节点高度 = `max(34, 16+12)` = **34px**，图片区可用高度 = `34-8` = **26px**
- 任意正常宽高比的图被 `meet` 压进 26px 高的带子 → **严重压扁**
- 文本在 `<image>` 之后渲染（SVG 绘制顺序 = 层叠顺序），**文字直接压在图片上**
- 图片与文本争用同一块垂直空间，二者语义混杂（既当背景又当内容）

**性质**：这不是「观感不佳」，是**资产预览功能在设计上不成立**——布局层与渲染层对节点高度的认知不一致。

### 🔴 P0-2 · glass 主题连线对比度不足

**证据**：`tokens.ts:107` `linkStroke: '#3a3f4d'`，画布底色 `#16181d`。

**量化**：相对亮度 L(#16181d)≈0.0086、L(#3a3f4d)≈0.0552 → **对比度 ≈ 2.3:1**，低于 WCAG 非文本元素建议的 3:1。深色主题下连线近乎不可见，直接损失「树状结构」这一核心认知线索（classic 主题 `#8a847a` 与 sticker 主题 `#c9c4b8` 均无此问题）。

### 🟡 P1 · 展开态（快速注释）注释区视觉缺陷

**证据**：`NodeG.tsx:104-123`
- 注释区 `<rect rx={style.radius}>` **四角全圆**——与本体连体处出现圆角缺口，视觉断裂
- `y = bodyH` 与本体底边同坐标 → 本体底边 stroke + 注释区顶边 stroke + 分隔线 `<line>`（opacity .5）**三线叠加**成粗重横线

### 🟢 P2 · 其他

- `<image>` 无 `onError` 兜底：资产 404 时无任何降级提示（仅剩文本，用户无法判断是「无图」还是「图挂了」）
- 图片 `opacity 0.92` + 文本覆于其上：复杂底图上文字仍可能不可读（修 P0-1 后不再重叠，本项自动缓解）

### ✅ 经源码核对「不成立」的质疑（撤回）

| 推测的问题 | 源码核对结果 |
|---|---|
| `@img` 文字角标与文件名抢空间 | **排版正确**：`contentX = PAD_X + kindW + 6`，`chipXOf` 反算回 `PAD_X`，kindLabel 与文本水平相邻不重叠 |
| 折叠三角在右下角（与下拉菜单歧义） | **位置正确**：`translate(b.w - 12, bodyH / 2)` = 右侧垂直居中，思维导图常规位置 |
| 节点层级无视觉区分 | **已实现**：`leaf = depth >= 2` 切换 `sizeLeaf` 字号；`fontWeightRoot` 区分根节点 |

## 三、修复方案（已实施）

| 项 | 修复 | 文件 |
|---|---|---|
| P0-1 | 内核 `displayMetrics` 对 `img`/`draw` kind 追加可选 `assetH`（默认 96），高度公式纳入资产区；NodeG 改为**卡片式**：图片占顶部独立区、文本区下移不再重叠 | `nodeLayout.ts` / `NodeG.tsx` |
| P0-2 | glass `linkStroke` `#3a3f4d` → `#646b7d`（对比度约 3.4:1） | `tokens.ts` |
| P1 | 注释区改用 path 手绘「上半直角 + 下半圆角」；去掉冗余分隔线，消除三线叠加 | `NodeG.tsx` |
| P2 | `<image>` 加 `onError` 降级（加载失败时隐藏图片区，仅显示文本） | `NodeG.tsx` |

## 四、冻结合规说明

- `DisplayMetrics` 新增 `assetH?: number` **可选字段** → 符合 ADR-0004「minor 可加不可改」
- 高度变化仅作用于 `img`/`draw` kind 节点（当前渲染本就不可用，属 bug 修复而非破坏性变更）
- 已记入 `CHANGELOG.md` 1.0.1 patch 条目

## 五、遗留建议（未在本轮处理）

1. 资产宽高比应由内核按实际图尺寸计算（当前固定 96px，需资产尺寸元数据）
2. `@draw` 可编辑绘图需要独立编辑入口（M2 范畴，非渲染 bug）
3. 资产加载中的占位骨架屏（当前加载期间为空白）
