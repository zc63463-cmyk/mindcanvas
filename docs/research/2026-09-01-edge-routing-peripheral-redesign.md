# 连线路由重设计：从「最短路径」到「外围绕行优先」

> 日期：2026-09-01
> 触发：蒋指导「应当连线优先从外部连线，尽量少的穿线以及穿节点，
> 而不是一味追求最短路径，这个思路是错误的」
> 调研样本：XMind / MindManager / Miro / Obsidian Canvas / tldraw / draw.io / markvault-js + 图绘制美学实证文献

---

## 一、现状问题：优化目标错了

当前实现（trunk 折线绕行 + 网格 A* 兜底）的优化目标是**路径最短**。这是本末倒置。

A* 会为了最短而**钻节点之间的窄缝**：几何上确实不穿障，但视觉上是"从节点群里挤过去"，
既不美观也难追踪。这正是用户反复否定的效果。

| 维度 | 现状 | 问题 |
|---|---|---|
| 路径形态 | 多段折线（3–8 段） | 锯齿状，违反 Gestalt 连续性 |
| 优化目标 | 最短路径 | 图绘制美学中属末位准则 |
| 避障方式 | 在节点之间找通道 | 视觉上"穿过节点群" |
| 默认线型 | 折线 | 与全部 7 款参照产品均不同 |

---

## 二、理论依据：图绘制美学的优先级

Purchase、Cohen、James 的实证研究与后续复现一致给出：

| 优先级 | 美学准则 | 证据强度 |
|---|---|---|
| 1 | **最小化边交叉（edge crossings）** | overwhelming evidence，**over all other aesthetics** |
| 2 | 最小化边弯曲（bends） | partial support |
| 3 | 最大化对称（symmetry） | partial support |
| — | 正交性 / 最大最小角 | no support |
| 末位 | 最短边长 | 不在前两位 |

关键结论：

- **"最小化交叉"优先级高于"最短边长"** —— 我此前一直在优化末位准则。
- 研究记录的用户偏好：**把子树组件放在图的 outer face（外层面）** —— 即"外围绕行"。
- Gestalt「good continuation」：平滑连续轮廓比锯齿状更易辨识 → **单条曲线优于多段折线**。
- SBGN 规范：边可穿过节点，但应 **crossing boundary only twice**（直穿，不在内部绕）。

## 三、成熟项目参照（7 款横向对比）

| 工具 | 默认线型 | 避障方式 | 锚点策略 | 人工干预 |
|---|---|---|---|---|
| **XMind** | 单条贝塞尔曲线 | **调曲率**避开，无网格寻路 | 端点**沿主题边缘滑动**找 best position | control point 拖曲率；手动后不再自动 |
| **MindManager** | 贝塞尔曲线（形状可选） | **Auto-Adjust 最优路径**（曲线自适应） | 连接点可自由调整 | 手动 reshape → Auto-Adjust 自动禁用 |
| **Miro** | **curved（曲线）为默认值** | Auto-routing 找 best path | 归一化坐标（0–1）+ snapTo | waypoints / bends 可调 |
| **Obsidian Canvas** | default 为曲线 | **A\* 仅为插件可选项**，原生默认不寻路 | — | straight / squared / A\* 可切换 |
| **tldraw**（Miro/FigJam 引擎） | 直线 / 曲线二选一 | **不自动避障** | **归一化锚点 + 射线求交**；按相对位置选边 | bend handle 调曲率 |
| **draw.io** | Floating connector | 正交 / A\* 路由（需显式开启） | floating 沿边缘找最短路 | waypoints |
| **markvault-js** | trunk 折线 | 绕 X / 绕 Y 折线绕行 | 中心锚点 | 无 |

### 3.1 三条决定性共识

**① 默认全是曲线，没有一家用"多段折线绕行"作默认。**
XMind 单条贝塞尔、MindManager 贝塞尔、Miro 的 shape 默认值即 curved、
Obsidian default 为曲线。走折线绕障（我当前的 trunk/A\*）在成熟产品中属异类。

**② "最短路径"只是 center-to-center 连接的特例，不是普适目标。**
Miro 文档明确：拖到对象体出现蓝框 = center-to-center = shortest path；
而**边缘 anchor 连接「does not adjust to find the shortest path」**。
即产品把"最短路径"降级为一种可选连接模式，而非全局优化目标。

**③ A\* 是可选 / 插件级能力，不是默认主路径。**
Obsidian Canvas 社区插件把 `default / straight / squared / A*` 并列为
Pathfinding Methods 供用户选；draw.io 也需显式开启路由。

### 3.2 值得直接借鉴的四项具体机制

1. **归一化锚点（0–1）+ 射线求交**（tldraw / Miro）
   锚点存为形状内归一化坐标，形状缩放/移动后保持相对位置；
   求交时"从对侧 handle 投射射线"与目标边界求交，取中点并归一化。

2. **按相对位置选锚点表**（tldraw）

   | 相对位置 | 锚点策略 |
   |---|---|
   | 左对齐 | 右边缘中点 |
   | 右对齐 | 左边缘中点 |
   | 上对齐 | 下边缘中点 |
   | 下对齐 | 上边缘中点 |
   | 对角线 | 最近角点 |

3. **bend / control handle 调曲率**（XMind control point、tldraw bend handle）
   曲线弯曲程度由独立控制点决定，是"外绕"的主要调节手段。

4. **Line jumps 跳线**（Miro）
   交叉无法避免时让交叉**可读**（一条线跨过另一条画小弧），而非强行消除交叉。
   限制：仅 straight / orthogonal 线型支持。

### 3.3 手动覆盖约定（三者一致）

XMind / MindManager / Miro 均遵循：**用户一旦手动调整连线，自动优化即停用**，
需显式重新启用才恢复。这是尊重人工干预的标准交互契约。

## 四、新方案：曲率自适应贝塞尔（Curvature-Adaptive Bezier）

### 4.1 评分优先级（替代"最短路径"）

```
1. 不穿节点     硬约束（穿则淘汰，不参与评分）
2. 走外围       曲线朝布局中心凸 → 罚分（鼓励向外鼓）
3. 少交叉       与已有边相交 → 罚分
4. 少弯曲       曲率绝对值大 → 轻罚（鼓励平滑）
5. 短路径       长度 → 轻罚（末位）
```

### 4.2 搜索空间（枚举，非网格寻路）

- **锚点对**：源 / 靶各取边缘候选点（可在边上滑动，如每边 3 采样点 × 4 边 = 12 个）
- **曲率档位**：c ∈ {-1.0, -0.7, -0.45, -0.25, 0, 0.25, 0.45, 0.7, 1.0}
  （负 = 朝一侧凸，正 = 朝另一侧凸）
- 组合数约 12 × 12 × 9 ≈ 1300，可按锚点距离排序 + 早停剪枝

对每个组合生成三次贝塞尔，采样后按 4.1 评分，取最高分。

### 4.3 与旧方案的本质差异

| | 旧（trunk / A\*） | 新（曲率自适应） |
|---|---|---|
| 路径形态 | 多段折线（3–8 段） | **单条平滑曲线** |
| 优化目标 | 最短路径 | **外绕 + 少交叉** |
| 避障方式 | 在节点之间找通道 | **调节曲率向外鼓** |
| 视觉 | 折来折去、钻缝 | 一条外围弧线（XMind / Miro 观感） |
| 多线协调 | 无 | 交叉罚分，曲率错开 |
| 行业对齐 | 异类 | 与 7 款参照产品一致 |

## 六、风险与对策

| 风险 | 对策 |
|---|---|
| 枚举组合数偏高（~1300）影响帧预算 | 排序早停剪枝；关系边数量稀疏；已有 LOD 门控与路由缓存 |
| 交叉罚分需跨边协调，破坏按边独立缓存 | 缓存 key 加入边集版本；或按边序渐进协调 |
| 曲率档位 / 罚分权重需调参 | 切片 4 专做视觉验收调参（HITL） |
| 极端密集场景可能无解 | 降级为直穿（SBGN：crossing boundary only twice 可接受） |
| 曲线无法使用 Miro 的 line jumps（仅直线/正交） | 见 7.3：保留折线退路 + 自绘跳线弧 |

## 七、已决事项（蒋指导拍板）

### 7.1 降级策略：**允许直穿**

密集 / 无解场景不再强行寻找绕行路径，允许连线**直穿节点**，但须满足
SBGN 约束：**crossing boundary only twice**（直着穿过去，不在节点内部绕行）。

理由：一条"明确穿过卡片"的直线，比一条"看似绕开、实际仍穿障"的折线更诚实、更易追踪。
这也与 4.1 的硬约束（不穿节点）形成分级——能绕则绕，不能绕则**直穿而非乱绕**。

### 7.2 手动覆盖：**纳入首期**

遵循 XMind / MindManager / Miro 一致的交互契约：

- 用户一旦手动调整某条连线（拖端点 / 拖 bend 控制点），该线的**自动优化即停用**
- 需显式操作才恢复自动（如 MindManager 的 Auto-Adjust 重新勾选）
- 此状态需持久化（存于边的 style / 扩展字段），重载后保持

### 7.3 Line jumps：**需要，保留折线退路**

因 Miro 的 line jumps 仅支持 straight / orthogonal 线型，曲线无法直接套用，故：

- 保留**折线退路**：需要跳线渲染时可从曲线退化为折线（正交段 + 跳线弧）
- 或**自绘跳线弧**：在曲线交叉点处绘制跨越小弧（不依赖线型）
- 跳线目标：交叉**可读**——明确哪条在上、哪条在下，而非强行消除交叉

### 7.4 附：评分优先级最终版

```
1. 不穿节点     硬约束 —— 但无解时允许「直穿」（7.1），不得「乱绕」
2. 走外围       朝布局中心凸 → 罚分
3. 少交叉       与已有边相交 → 罚分（交叉不可避免时由 line jumps 兜底，7.3）
4. 少弯曲       曲率绝对值大 → 轻罚
5. 短路径       末位轻罚
6. 人工锁定     用户手动调整过的边跳过上述全部自动优化（7.2）
```
