0TL;DR：五条结论

趋势

热点已从「画布」转到「AI Agent × 画布」

本周 JS/TS trending 前排全是 agent 工具链，画布类零上榜。但 topic infinite-canvas 近一年新增高星项目（opencove 1.6k、horizon 705、thoughtdag 416、dim0 132）清一色是 agent 工作区。

卡位

「纯文本事实源 + 自由摆放」几乎空白

Markmap/Mermaid 纯文本但强制自动布局；Obsidian Canvas 自由摆放但事实源是 JSON；Excalidraw/tldraw 自由但事实源是自家快照。mindcanvas 的 .mm.md + 坐标覆盖正好落在这个空档。

选型

不建议依赖任何白板 SDK

tldraw 生产需商业许可（非 OSI + 强制水印）；Excalidraw SDK 344kB gzip 且有 breaking 史；xyflow 的分组/自动布局/撤销在 Pro 付费层。借鉴架构，不引依赖。

性能

SVG 还能撑很久，先别换渲染器

实测临界点在「可见节点数千」量级（5000 节点 SVG ~150ms/帧 vs Canvas 12ms）。mindcanvas 已有裁剪 + LOD，真实可见数远低于此。先补四叉树与 transform-only。

抄作业

最值得抄的三处设计

① Excalidraw：Elements 与 ViewState 分离 + version/nonce 合并；② tldraw：signals + record store + 剔除 + LOD；③ JSON Canvas：nodes/edges 两数组 + 纯 JSON 可 diff。

4性能与渲染专题：SVG 的天花板与切换阈值

经验法则

静态 SVG ≤500–1000 元素安全，动态 >2000 应考虑 Canvas（blog.vijayt.com）。Figma 的结论更本质：GPU 渲染成本按像素而非对象数计费，10 个与 5 万个形状开销相近；Miro 用 WebGL + 四叉树 + 实例化做到 10 万 widget 保 60fps。

4.2 无限画布的标准优化套路

  1. 视口裁剪 / 虚拟化：tldraw 用空间索引 + display:none，"10000 形状可能只渲染 50 个"；Excalidraw isElementInViewport，>500 元素就有明显收益。mindcanvas 的 CULL_MARGIN=128 属合理量级（最优值未实测）。
  2. LOD：tldraw 缩小时图案转纯色、关文字阴影、简化几何；Excalidraw 网格 actualGridSize<10 不画。
  3. 空间索引：四叉树 / R-tree / 网格，命中测试 O(N)→O(logN)。tldraw / Miro 均用四叉树。Excalidraw 直到 2025-12 才有 PR #10514 补（未合入），说明 O(N) 在数千规模下确实会卡。
  4. 批处理 / 分层 / 离屏：Excalidraw 静态层 + 交互层分离；脏矩形在 10–20% 区域变化时省 70–80% 渲染。
  5. 绕开 React 重渲染：tldraw 相机移动直接 setProperty 改 CSS transform；signals 只更新变更 shape。
  6. 命中测试方案对比：SVG 原生事件最省；几何检测（反序 + 包围盒）10,000 点 5–20ms；isPointInPath 10,000 次需 2000ms（仅适合 <100 图形）；拾色缓冲（color picking）0.1ms、O(1)，Konva 采用，适合图形多且不常重绘。

4.3 平移 / 缩放的正确做法与坑

做法

  • 用 transform 全局矩阵，而非逐元素重排（Excalidraw 一次 ctx.transform 投影）。
  • Canvas 下按 DPR 放大缓冲区：canvas.width = rect.width * dpr + ctx.scale(dpr,dpr)。

坑

  • CSS translate 位移上限约 ±10,000,000px，超大画布会被截断。
  • 缩放必须重绘路径，否则矢量拉伸模糊；DPR 处理不当 Retina 上文字发虚。

5趋势判断：真需求 vs 噪音

真实需求

  • AI 生成式画布：tldraw Make Real（草图→HTML）、Flowith（非线性思考工作区）、Napkin / Gamma（文本→视觉资产）已跑通商业形态；本轮 topic 榜单里 opencove / thoughtdag / dim0 / horizon 全是这个方向。
  • 协作 + CRDT / local-first：tldraw-sync、Excalidraw E2EE、Yjs / Automerge 已成标配。
  • 开放可 diff 格式：JSON Canvas（MIT）已被 Obsidian 生态采用；OCIF（CC BY-SA 4.0，2026-03 v0.7 候选）正在做跨工具互通标准。

噪音

  • 大量"AI Agent 无限画布"只是 GPT 包装层，无数据模型创新；"无限 agent 步数 / 上下文"多为营销。
  • 单纯"手绘风白板"赛道已极度内卷（Excalidraw 131k★ + tldraw 50k★ 双寡头），新进入者没有差异化就别做。

6对 mindcanvas 的落地建议

P0 — 立刻可做、收益确定

  1. 不要把白板 SDK 作为依赖引入。 tldraw（生产付费 + 水印）、Excalidraw SDK（344kB gzip + breaking 史）、xyflow（核心能力在 Pro 付费层）都不划算；继续自研 kernel + SVG。若未来必须引入，唯一无许可雷的是 quickdraw（MIT，但 v0.2.0，只作观察对象）。
  2. 加空间索引：命中测试与可见性查询从 O(N) 换成四叉树 / 网格 O(logN)。触发阈值：总节点 > 1000 或可见节点 > 300 时启用。
  3. transform-only 更新：平移 / 缩放一律走 CSS transform / setProperty，禁止逐节点 React 重渲染；节点 > 500 时禁用逐节点 state 更新。

P1 — 短期（1–2 个迭代）

  1. LOD 判定改为「zoom 分级 + 平移期冻结」：当前按总节点数判定会导致平移时整体跳变；改为按屏幕尺寸（节点 < 24px 或 zoom < 0.3 降级），并在手势期间锁定等级、手势结束再重算。
  2. 裁剪 margin 自适应：CULL_MARGIN=128 保持默认，当可见节点 > 2000 且帧率 < 50fps 时动态扩大 margin，减少进出抖动导致的反复挂载。
  3. 对齐 JSON Canvas 作为交换格式（只做导入导出，不改事实源）：.mm.md 仍是唯一事实源，额外支持导出 .canvas（nodes/edges 两数组），直接吃下 Obsidian 生态，把既有的「自由连线 + 多中心升格」成果变成可互操作资产。
  4. 文件格式版本化：学 Excalidraw 的 version 字段 + migration 函数链，为 .mm.md 的 note 协议（v1.4）升级做准备，避免将来靠 parse 兜底。

P2 — 中期（需要摩擦驱动，不要提前做）

  1. AI 只做"薄生成层"：让 AI 以「追加可 diff 的 .mm.md 文本片段」方式生成导图，先在内存预览再落盘（与既有"AI 改动先进预览再确认"一致）。不要现在就做画布内多模态生成或长链路 agent 管线。
  2. 协作：若出现 ≥2 条跨文档真实摩擦再启动；届时优先 Yjs（local-first），不要自造同步后端。
  3. 渲染器切换：只有同时满足「可见节点 > 5000 且帧率 < 30fps」或「总节点 > 20000」时才启动混合方案评估；WebGL 之前先读 xiaoiver/infinite-canvas-tutorial。

明确不做

  • ❌ 为追 Excalidraw 的手绘风切 Canvas —— 会丢掉中文文本、无障碍、可选中、可 diff 的差异化优势。
  • ❌ 依赖 tldraw / xyflow Pro 等带付费或水印的组件。
  • ❌ 现在上协作、上 AI agent 画布 —— 没有真实摩擦驱动就是治理动作。
