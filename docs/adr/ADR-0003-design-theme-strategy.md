# ADR-0003 · 多主题设计策略（V1 经典曲线 / V7 画布贴纸 / V8 玻璃现代）

| 项 | 值 |
|---|---|
| 日期 | 2026-08-27 |
| 决策人 | 蒋指导（钦定）、WorkBuddy（设计执笔） |
| 状态 | 已接受（K3 渲染层的视觉纲领） |
| 上游 | 设计调研报告 `docs/preview/mindmap-design-styles-report.html`；roadmap K3 段 |

## 决策

1. **多主题并存，而非单一主题**：mindcanvas 首期交付三套主题——**V1 经典曲线**（XMind 谱系）、**V7 画布贴纸**（Miro/FigJam 谱系）、**V8 玻璃现代**（Linear/Arc 谱系），运行时一键切换
2. **主题 = 设计令牌集（TokenSet），不是三套组件**：三主题共享同一渲染核心，差异全部收敛在令牌层——颜色 / 圆角 / 间距 / 字体 / 动效 / 连线样式 / 阴影。渲染器按令牌参数化（节点形态、连线语言是令牌驱动的高级差异）
3. **应用外壳（chrome）固定玻璃工具感**：面板 / 标签 / **翻卡等交互组件**用深色半透明 + 霓虹强调（V8 气质）——画布本体主题可换，外壳风格恒定
4. **默认主题 = V8 玻璃现代**（用户翻卡选择所指），V1/V7 作为可切换主题

## 理由

- 用户诉求：「V1/V7/V8 都想要」——三套主题覆盖三种心智场景（演示交付 / 协作发散 / 沉浸工具），切换成本由令牌架构摊薄
- 设计令牌分层能力（R14 库优先 + K3 令牌先行）本就为此而生：主题是渲染侧的「内置插件」，与六注册表精神一致
- 玻璃 chrome 统一交互层气质，避免外壳随画布主题漂移造成认知混乱

## 被否选项

- **单一主题**（V8 独享）：丢失 V1 的正式感与 V7 的承载感，且用户明确要三者
- **三套独立组件**：组件 × 主题矩阵爆炸，违反「风格迭代只动 tokens 层」纪律（roadmap 风险对策）
- **V2 文本极简入首期**：与纯文本内核气质最合，但用户未选；列为二期候选（实现成本最低，随时可加）

## 主题集定义（首期三套）

| 主题 id | 谱系 | 节点形态 | 连线语言 | 配色 | 典型场景 |
|---|---|---|---|---|---|
| `classic` | V1 XMind | 圆角矩形 + 图标位 | 彩色曲线贝塞尔 | 每分支一色（高饱和） | 演示 / 正式交付 |
| `sticker` | V7 Miro | 贴纸卡片（阴影） | 任意曲线 | 多彩贴纸色 | 协作 / 发散-收敛 |
| `glass`（默认） | V8 Linear | 半透明圆角卡 | 柔和贝塞尔 | 深底 + 霓虹强调 | 沉浸 / 夜间深耕 |

## 后果

- 渲染核心必须令牌参数化：节点渲染器（矩形/卡片/玻璃）+ 连线渲染器（曲线/任意/柔和）按 TokenSet 分支，**组件逻辑不得写死视觉值**
- K3 任务书按此决策锁定方向；视觉快照（三主题各一张 demo 导图）作为验收基线存档
