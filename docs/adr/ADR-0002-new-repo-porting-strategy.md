# ADR-0002：新仓库演进策略（只读参考源 + 分阶段移植 + 归档）

| 项 | 值 |
|---|---|
| 日期 | 2026-08-27 |
| 状态 | 已接受（K0 定案） |
| 上游依据 | 内核重构路线图 · 总览与风险表；联动 spec §4.6（R12） |

## 背景（Context）

- 双仓库并行：knowledge-canvas（旧，功能成熟）与 mindcanvas（新，内核重构）；
- 跨仓库移植有成本（路径/依赖修正）；双线并行有负担（重复维护、行为漂移）；
- 总原则「移植而非重写」：成熟资产（协议层/326 测试/布局引擎）按阶段搬运，债务（44KB MapView 等）重写。

## 决策（Decision）

1. **knowledge-canvas 降级为只读参考源**：K0 启动即冻结其功能新增（只修 bug）；`src/protocol/`、协议相关测试、布局引擎是 K1/K2 的移植出处。
2. **K1 协议层与测试目录级整体拷贝**（再修 import，不做逐文件挑选），避免选择偏差与遗漏；golden cases 随迁。
3. **K4 对齐验收后旧仓库归档**：README 标注继任者 mindcanvas（描述、链接、数据格式兼容性说明）。

## 理由（Rationale）

- 「移植而非重写」降低协议层回归风险（326 测试资产直接复用）；
- 目录级拷贝消除「人工挑选」带来的漏移植/不一致；
- 新仓库干净地基承接 K1-K5 阶段门禁，门禁不绿不进段（路线图启动方式 §2）。

## 后果（Consequences）

- 正面：新仓库协议层可逐阶段与旧仓库抽样 diff 对齐（K1 验收）；旧仓库行为冻结，双线负担收敛；
- 义务/风险：K1 移植前，新内核的 parse/serialize 仅为最小占位（T5 已标注「勿扩展，K1 整体替换」）；K4 前旧仓库仍需维护（修 bug），不可提前归档。

## 被否选项（Alternatives considered）

| 选项 | 结论 | 理由 |
|---|---|---|
| 在旧仓库原地重构 | 被否 | 44KB MapView 等债务需重写，混在新仓库干净地基中更稳；架构范式（微内核/插件/库优先）无法在旧结构上渐进成型 |
| 一次性复制全部代码到新仓库 | 被否 | 与 K0-K5 分阶段验收门禁冲突，无法按阶段控制风险 |
| 旧仓库即时归档 | 被否 | K4 前仍需要参考源（协议层/测试/布局引擎移植出处） |
