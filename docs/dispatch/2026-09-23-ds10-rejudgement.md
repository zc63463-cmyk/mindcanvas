## 0. 裁定结论

**维持「当前不删」的运行时状态不变，但将选项 (b) 细化并批准为 (b')，作为一个专用小批（DS-10 实施批）在 P0-B 之前实施。**

(b') 定义：**在降级投影中，移除「已被某条目认领（双形态）∧ 不是任何条目的当前投影 id ∧ 行本身可解析」的旧库行**。它不需要原 (b) 所需的「迁移完成」全局信号——每一行独立判定。

## 2. 原 (b) 阻塞的解除：逐行判据 (b')

原复核的阻塞是「无可判定的迁移完成信号」。复审确认该阻塞可**绕过**——不需要全局信号，每一行独立判定：

**可删(X) := X ∈ ⋃ legacyKeys（双形态：明文 `X`，或 `mindcanvas.library.v1#X` 前缀形态）∧ X ∉ { legacyIdOf(e) : e ∈ docs } ∧ X 可解析（在 byId 内，非 opaque）**

双形态的实证：M5 迁移以**前缀形态**认领旧库行（`docIndexMigrate.ts:108,172`：`legacyKeys: ['mindcanvas.library.v1#'+key]`，且 `existing` 查找同时认 `e.relPath === key` 与前缀形态），而 `relocateEntries:80-83` 以**明文形态**追加。`projectStarred:172` 已有 `⋃ legacyKeys` 的现成计算可复用。

**与原三条不变量的对照**（逐条实读验证）：

| 不变量 | (b') 下是否成立 | 依据 |
|---|---|---|
| 孤儿行（从未认领）保留 | ✅ 成立 | X ∉ ⋃ legacyKeys → 不可删 |
| 畸形/损坏行保留 | ✅ 成立 | 不可解析 → 不在 byId → 不可删；`:236` 的 `failed` 断言（N-2）不受影响 |
| 尚未迁移的旧键不被投影破坏 | ✅ 成立 | 未迁移 ⇒ 未被认领 ⇒ 不可删；且迁移本身不产生 superseded 行（M5 认领的行其 relPath 即行 id，是「当前」而非「被取代」） |
| 幂等（QUAL-C） | ✅ 成立 | 清理只发生在投影；首次清理后行集稳定，纯 `migrate()` 仍不碰旧库 |
| 降级视图正确性 | ✅ 改善 | 降级 app 从「同一逻辑文档两行」变为「一行（当前路径）」 |

## 3. 复审新发现（原复核未覆盖，实施批必须处理）

**F3 部分成功残留**：move 目标已写、源删除失败时，源文件**仍在磁盘上**，而编排层已把会话搬到新位置（`relocateDoc` 已认领旧键）——此时旧行满足 (b') 的全部可删条件，但它是「仍在磁盘上的源文件」在降级视图里的唯一代表。盲目执行 (b') 会丢掉这个代表（磁盘数据不受影响，可被重新扫描发现，但降级 app 的列表视角缺一项）。

**裁定约束**：实施批必须把 F3-部分成功的源键排除在删除之外（例如：删除判据消费操作结果——rename 成功 / move 成功才删；或投影期显式跳过未消解的 partial 键），并为此配判别性负控。具体机制由实施批定，但**不得**以「盲删 + 文档备注」了事。

## 4. 实施批范围与纪律（DS-10 实施批，P0-B 之前）

**范围**：`docIndexProject.ts` 的 projectLibrary 行集构建（+ 可能的编排层删除信号）；不动 migrate、不动索引写入口纪律。

**必须守住的六条**（§2 五条 + §3 一条）：
1. 孤儿行保留；2. 畸形行保留；3. 未迁移键不被破坏；4. 幂等；5. 降级视图一行一文档；
6. **F3-部分成功的源行保留**。

**写入纪律**：library.v1 的写入口现状为投影（`replaceAll` + N-1 写后回读校验）与 `DocLibrary.save`（生产保存单行 upsert）。实施批若新增针对性删除，必须走既有公开读取面/写入面，并把新路径纳入回读校验口径，不得引入绕过 N-1 校验的第三写路径。

**必须的五条判别性负控**（中性化→落盘校验→转红原文+退出码→cmp 还原→回绿，六要素齐备）：
1. 中性化删除判据 → 被取代的旧行重新出现（残留复现）→ 必须转红；
2. 删除判据扩到孤儿行 → 孤儿行丢失 → 必须转红；
3. 删除判据扩到畸形行 → 必须转红；
4. F3-部分成功源行被删 → 必须转红；
5. 投影跑两次 → 行集一致（幂等）→ 中性化后必须转红。

**门禁**：冻结基线（lint 1541/48 注意：P0-A 后已变为 1536/48，以开工实测为基线、只减不增；budget 八项；kernel 708 / react / canvas 全量只增不减；doc-index 67 条零回归）。

## 5. 附带观察（不阻断，记录在案）

**starred 侧的前缀不对称**（实读发现，先于本裁定存在）：M5 的收藏认领用前缀形态 `mindcanvas.starred.v1#<key>`（`docIndexMigrate.ts:238`），而 `projectStarred:172,184` 的 `claimed` 检查是**明文**查找——于是「M5 迁入后取消收藏且从未改名」的旧收藏键会被投影**保留**（降级视图残留一个星标）。方向保守（不丢数据），且改名后会因 `relocateEntries` 补了明文认领而自然收敛。实施批实现双形态认领助手时，应顺手让 starred 侧复用同一助手，消除该不对称；若不做，需在回执中明示。
