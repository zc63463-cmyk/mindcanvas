### 1.1 产品 UI 侧：合规

裁定书原本担心「界面文案里有没有跨浏览器承诺」。逐处核查后，**产品源码侧全部合规**：

**观察到的正面模式**：用户可见文案统一用「**当前环境不支持**」这一环境相对表述，而不是「本浏览器不支持」或「支持 X 浏览器」。这是**比 G11 纪律要求更稳的写法** —— 它不承诺、也不否定任何浏览器。此模式应作为后续新增文案的模板。实测的两处样例：
- `apps/canvas/src/hooks/useExportActions.ts:79`：「当前环境不支持导出 PNG，已改为导出 SVG。」
- `apps/canvas/src/hooks/useFreeCanvasDocument.ts:160`：「已下载 JSON（当前环境不支持直接写回文件）」

**扩大扫描**（对 `README.md` / `CHANGELOG.md` / `docs/specs/*.md` 扫 `支持.*浏览器|浏览器.*支持|兼容.*浏览器`）：**除 `CHANGELOG.md:70` 外无其他命中**。即这一处是当前唯一的 G11 纪律违反点，不是普遍现象。

### 1.2 CHANGELOG 侧：发现违反

**位置**：`CHANGELOG.md:70`

```
真浏览器矩阵 106 断言全绿（Windows Chromium：创建两跳 / 成员增删降级 / 左向岛 /

`outputs/summary-node/S5/S5-20260921-230000/browser/`）
```

**为什么违反**：`docs/specs/2026-09-19-file-assets-design/acceptance-and-backlog.md:42` 的纪律行明文规定

> **纪律**：G11 不得写成事实。

而「真浏览器矩阵 106 断言全绿（Windows Chromium：…）」是把**单一浏览器、单一平台的通过**写成了一句无范围限定的事实陈述。读者的自然读法是「浏览器兼容性已验证」。G11 表本身（`:35`）写的是「跨浏览器（Firefox / Safari）｜**未验证**……**本包不承诺**」——两处口径不一致。

**注意这不是「数值造假」**：106 断言的数字本身经核为真（`41 + 65` 个 `check(`，证据 `43 ✔ + 63 ✔`）。**问题在范围表述**，不在数字。

**同一段落里恰好有一句正确的写法可作参照** —— `CHANGELOG.md:88-89`：

```
S5-R2 于 Mac 复测见 R2 回执 §五；Mac 构建产物 `main-BgdfvXm7.js` 与 Windows 浏览器
证据 bundle **sha256 逐字节一致**（159e2d1a…，450702 B），浏览器矩阵证据据此沿用。
```

这一句把「沿用」关系说清了。但它仍然**没有点明「Windows = 单一平台、Chromium = 单一浏览器，跨浏览器未验证」**，也没有说明「沿用」是对证据强度的让渡。

**建议改法（供主控定）**：在 `:70` 的陈述后补一句范围限定，例如

> 该矩阵为**单一浏览器（Chromium）、单一平台（Windows）**；Firefox / Safari 与跨浏览器行为**未验证**，见设计文档 G11 的「本包不承诺」。

并在 `:88-89` 的「沿用」句后点明让渡性质（沿用 = 以产物字节同一性替代在另一平台重跑，不是在该平台复现）。**本报告不直接修改 CHANGELOG** —— 措辞与是否修改由主控决定。

## 核查二 · `outputs/` 证据引用措辞（裁定书 §3.2）

**结论：5 处引用，全部指向 `main` 上不可达的路径；裁定书所述行号准确。**

### 2.1 可达性实测

```
git ls-tree -r --name-only HEAD -- outputs/ | wc -l   →  0
```

`CHANGELOG.md` 中 5 处 `outputs/summary-node` 引用：`:22`、`:25`、`:73`、`:76`、`:82`。
（裁定书写的是 `:25/73/76/82` 四处，实测为**五处** —— 我漏了 `:22`，此处更正。）

| 行 | 引用内容 |
|---|---|
| `:22` | S4 证据目录 `outputs/summary-node/S4/S4-20260921-160000/` |
| `:25` | S5-R2 证据目录 `outputs/summary-node/S5-R2/S5-R2-20260922-142654/` |
| `:73` | 106 断言浏览器证据 `…/S5/S5-20260921-230000/browser/` |
| `:76` | 阴性对照证据 `…/S5-R2/S5-R2-20260922-142654/negctl/` |
| `:82` | closeout.md `…/S5-R2/S5-R2-20260922-142654/docs/closeout.md` |

### 2.2 性质

这些路径**在旁支可达**（`codex/summary-node-s5-r2-20260922` 有 210 个 `outputs/` 文件，`git cat-file -e <branch>:<path>` → exit 0），**在 `main` 不可达**。而 `.gitignore:43` 是 `outputs/` 整体忽略、**无任何否定规则**，所以它们在 `main` 上永远不会出现。

因此这不是「文件丢了」，而是「**发布记录引用了一组不在发布线上的证据**」。CHANGELOG 的语气（「落盘」「证据」）让读者以为可直接打开。

### 2.3 建议改法（供主控定）

三个层次，按代价从小到大：

| 方案 | 动作 | 代价 |
|---|---|---|
| **① 改措辞（必做）** | 在段落首处加一句总声明：「本节引用的 `outputs/**` 证据位于旁支 `codex/summary-node-s5-r2-20260922`，未并入本分支；`main` 上不可直接打开。」 | 极低 |
| ② 停止引用落空行号（必做） | 把裸路径改为「见旁支 `<branch>` 的 `<path>`」形式，避免读者在 `main` 上按路径找 | 低 |
| ③ 合入证据（条件性可选） | 把 `outputs/summary-node/S5{,R2}/**` 合入 `main`，并补 `.gitignore` 否定规则 | 中；且需先定证据入库规则 |

**① 与 ② 是裁定书里写的「必做」，③ 是可选。** 本报告不代改。

**为什么值得单列**：它自称「如实」，却给读者一个与代码相反的事实。这比核查一那句范围表述更直接 —— 范围表述是「没说全」，这句是「说反了」。
