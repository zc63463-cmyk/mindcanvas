### 5.3 一处既有测试的**期望不变**的健壮性修复（须逐条说明）

`apps/canvas/tests/mode-guard.test.tsx` 的 `flush()` 从「等 0ms」改为「等 20ms」。

- **原断言 → 新断言**：**断言一字未改**（`expect(saveState(container)).toContain('未保存')`
  等全部原样保留），只改了「两次事件循环之间等多久」。
- **为什么原写法有问题**：该文件的 `requestAnimationFrame` 桩是 `setTimeout(cb, 16)`
  （`:160`）。`flush()` 只等一个 0ms tick，「编辑 → dirty」要经历的那次 rAF 回调
  **是否已执行**取决于事件循环里还排着多少别的定时器 —— 单文件跑够用，同批多一个稍慢的
  文件就不够。
- **实证（不是推测）**：`mode-guard` + **任意**一个约 1.5s 的空转文件即转红
  （`expected '✓ 已保存' to contain '未保存'`）；**该现象在 P0-B 之前的基线提交上同样复现**
  （`git stash` 后放一个 `setTimeout(1500)` 空转文件即可）。因此这是该文件**既有的调度脆弱性**，
  本包只是新增测试拉长套件后把它触发出来。
- **修后**：`mode-guard` + 1.5s 空转文件 12/12 绿；全量 56 files / 625 passed。
