### 为什么收工的产品树锚与期望不同（**不是漂移**）

`HEAD:packages` / `HEAD:apps` 是「**被提交的那棵子树**」的哈希 —— 本包改动了 `packages/`
与 `apps/` 下的代码，它们**必然**变。稳定判据要问的是「**开工时的基准**是否仍是期望值」，而不是
「收工时的树是否没变」（那等于要求不许写代码）。故用三条证据：

1. **开工提交 `3a192c1` 的两个产品树锚与期望逐字一致**：
   `git rev-parse 3a192c1:packages` = `c771dd3bc061b917a195ecf03ac73129c431df71` ✅
   `git rev-parse 3a192c1:apps` = `61d46757fbf5eb6cbd3c5b213294f4c4beae7369` ✅
2. **`4693d9b`（派单书原始基准）的两个锚也一致**（同上两值）—— 开工前没有别人动过产品树。
3. **线性祖先**：`git merge-base --is-ancestor 3a192c1 HEAD` 成立 → 无 rebase、无历史改写，
   本包的全部改动都是 `3a192c1` 之后的**追加提交**（§7 提交列表逐条可核）。

即：开工基准正确；收工锚的变化**全部来自本包自己的 14 个提交**，逐条在 §7 列出。

4. 磁盘文件 mtime **不变**（可用 `ls -l` 或系统文件管理器确认 —— 无新写入）；
5. 写入结束后重试改名 → 成功；此后再 Ctrl+S → 写入**新路径**，旧路径不再存在。
