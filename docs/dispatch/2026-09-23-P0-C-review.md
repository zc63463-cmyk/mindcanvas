## 4. 三个产品缺陷（源码机制独立复核）

### N1-ID-COLLISION（high）—— 成立，P0-B 残留

机制四跳全部实读命中：

1. `packages/react/src/chrome/idbAssetHost.ts:192`：浏览器素材库项 id = `assets/${name}`，
   与工作区磁盘引用**同 id 形态**；
2. `packages/react/src/chrome/workspaceAssetHost.ts:140-156`：挂载后 `listAssets` 合并
   清单时 `byId` 以同 id 用磁盘项**覆盖** IDB 项，且磁盘字节被预热进当前 scope 的 URL 缓存；
3. `packages/react/src/chrome/assetInsert.ts:178,221-241`：`normalizeToWorkspace` 经
   `bytesOf → readAssetFile → host.resolveAssetState(item)` 取字节；
4. `workspaceAssetHost.ts:173-188` + `assetHost.ts:262-264`：`isWorkspaceAssetRef` 纯前缀
   判定 → scope 缓存命中 → fetch 回的是**磁盘同名文件**字节。

结果：蓝图像字节被静默丢弃，`assets/a 2.png` 写入红图字节（N1.5 `a2BytesIsBlue=false`），
文档引用与「已保存副本」提示均成立——违反 I-10 规则 1「跨存储先复制字节再引用」的核心承诺，
属静默数据错误。P0-B §7-1 修了 `alreadyInWorkspace` 的**判据**（且该判据现在由调用方
账本显式给出），但**字节来源路径**未随同修复，回执定性准确。

### N1-REOPEN-BROKEN（medium）—— 成立；本审查把机制定位得比归档更确定，并发现 N4 同根

归档表述为「与插入会话遗留的实体状态相关」。我实读后的确定机制：

1. 插入归一化的落盘走 `assetInsert.ts:206 w.writeAsset(...)` **直写 WorkspaceWriter**，
   不经 `WorkspaceAssetHost.writeToDisk`——后者 :253 本会把 objectURL 记入 scope 缓存，
   归一化路径完全绕过它；`MindmapStage.tsx:2967-2999` 的 `normalizeInsert` 之后也没有
   刷新 assetList 或预热缓存；
2. 两个 listAssets effect（MindmapStage:1317 依赖 `[assetHost, writeLedger, workspaceReady]`、
   :1346 依赖 `[assetHost]`）在**文档切换**时都不重跑；
3. 渲染端 `MindmapStage.tsx:2167` 用的是**字符串版** `assetHost.resolveAsset(ref)`，
   `workspaceAssetHost.ts:159-163` 缓存 miss 后回落 fallback，IDB 也 miss → 返回
   `baseUrl + id`（对 `assets/` 引用是必然 404 的站点根路径）→ `<image>` onError
   → `✕ 资产缺失`（NodeG.tsx:139-196）；五态版 `resolveAssetState` 早已在 :185-187
   明确「不回落 baseUrl」，但渲染端没接它。
4. 对照组（同磁盘状态、不经插入会话直接打开）经过挂载期 listAssets，scope 缓存已预热
   → blob 正常。差异点确定，不是玄学。

**N4.3-N4.5 同根**：内置图标以实体子节点插入时序列为 `@draw:data:`，渲染同样走
NodeG 的实体 ref 分支（不经 `resolveNodeIcon`，后者 nodeIcon.ts:34 本会直接处理 data:），
字符串版 resolveAsset 对 data: 无特判 → `/data:image/...` 404。修复 ② 若把渲染端接到
五态版（`:175` data: 直接 resolved），N1 与 N4 的重开/同会话断图应一并消失。派单
（P0-FIX-R1）已按此写验收。

### F1-S2G-INTERMITTENT-BLOCK（medium）—— 机制成立；4/5 复现率我未亲自重跑

`hooks/saveGuard.ts:17 canWriteDoc` 要求 `syncedSourceRef === doc.source` 精确等值；
该 ref 的两个文档切换置位点在 `useDocumentSwitch.ts:86,90` 的 **useEffect** 内（effect
在 commit 后才跑）。「打开文档 → 立即编辑 → Ctrl+S」存在 effect 尚未提交的窗口，
整次保存被拒；重按即成功，无数据丢失。归档 5 次复跑 4 次拦截（F1F2-S2G-NOTE.md）。
本审查只做代码机制复核，浏览器复现率**未自验**，如实标注。
