## 你的角色

你是 mindcanvas 仓库的工程执行 agent。本阶段目标：**把「能用的编辑器」变成「用起来自然的思维导图产品」，并摸清大规模性能上限**。这是产品深度阶段，不是功能堆砌——每一项都要能在实际操作中**被感受到**。

## 背景（含实测基线，重要）

mindcanvas 是纯文本思维导图（内核 v1.0.1，`.mm.md` 为事实源）。K0-K5 完成了内核工程（协议/树/布局/渲染骨架/编辑器闭环/三主题），但**画布的产品深度尚未开始**：

| 能力 | 现状 | 缺口 |
|---|---|---|
| 节点拖拽重排 | ❌ 无（现有 `dragRef` 仅画布平移 pan） | 思维导图最自然的操作缺失 |
| 布局/折叠过渡动画 | ❌ 完全无（`transition/animate` 零命中） | 所有变化瞬间跳变 |
| 多选与批量操作 | ❌ 无（仅单选） | 基础能力缺失 |
| 性能基线 | 仅测到 2000 节点 | 更大规模未验证 |

### 实测基线（本次开工前实测，你的优化起点）

```
   5461 节点  布局中位数  31.0ms
  21845 节点  布局中位数 111.8ms
  87381 节点  布局中位数 377.9ms
```

**关键结论：布局引擎不是瓶颈**（87K 节点仅 378ms，扩展性良好）。真正的瓶颈在**渲染侧**：当前为 SVG 载体，千级以上节点 DOM 元素数量爆炸。因此 B 组的优化重心是**渲染与增量**，不是重写布局算法。

## 任务清单

### A 组 · 自然度（优先级高于 B 组）

#### T1 · 动画内核（FrameScheduler 扩展）

- 在 `scheduler.ts` 增加**动画模式**：动画期间链式调度帧（每帧 request 下一帧），动画结束/中断后**立即回归休眠**（hasPending=false）
- 提供缓动函数集（`easeOutCubic` / `easeInOutQuad` 等）与 `animate({ from, to, duration, easing, onFrame, onDone })` 原语
- **可中断**：新动画打断旧动画时，从当前插值位置继续（不跳回起点）
- **硬约束**：空闲 CPU ≈ 0 不可破——动画结束 3 秒内 rAF 调用次数必须归零（有测试证明）

#### T2 · 节点位置过渡

- 布局变化时（折叠/展开、节点增删、缩进/反缩进），节点从**旧坐标插值到新坐标**而非瞬间跳变
- 新增节点淡入、删除节点淡出（opacity + scale）
- 连线随节点同步插值（不能出现「节点动、线不动」的脱节）
- 实现要点：布局前后各取一次节点坐标快照（id → {x,y}），按 id 配对插值

#### T3 · 视口动画

- 聚焦跳转（Ctrl+F 搜索定位、Ctrl+D 大纲点击、Ctrl+0 适配视图）时**平滑平移缩放**，而非瞬间跳变
- 缩放以目标为中心插值（平移 + 缩放同时进行）

#### T4 · 缩放平移手感

- 滚轮缩放以**光标位置为锚点**（缩放后光标下的内容保持不动）
- 拖拽平移加惯性阻尼（松手后缓停）
- 缩放范围边界回弹（超出 min/max 时平滑回弹而非硬停）

#### T5 · 节点拖拽重排（自然度最大缺口）

- 拖拽节点 → 悬停到目标节点上 → 视觉提示（目标高亮 + 插入位置指示）→ 松手完成重排
- **必须走已有 `move-node` TreeOp**（不可直接改树），保证 undo/redo 正确
- 拖拽期间禁用文本选择、处理 pointer capture、Esc 取消拖拽
- 落到自身子树内 = 非法（会产生环），需拒绝并给出视觉反馈

### B 组 · 高性能

#### T6 · 增量布局

- `layoutMindmap` 支持可选「脏子树」参数：仅重算受影响分支，其余复用缓存坐标
- 正确性优先：提供对比测试——**增量结果必须与全量重算结果逐坐标一致**
- 目标：编辑单个节点时的重算耗时 < 全量重算的 30%（以 5461 节点为基准测）

#### T7 · 渲染后端抽象（为大规模预留）

- 定义 `RenderBackend` 接口（绘制节点/连线/文本的原语集合），实现 **SVG 后端**（包装现有逻辑）
- **本期不实现 Canvas 全量后端**，只完成抽象 + SVG 适配器，保证后续可切换
- 目的：为 T8 发现的规模上限提供升级路径，不阻塞当前交付

#### T8 · 大规模基准与降级策略

- 基准扩展到 5000 / 20000 / 50000 节点，**分别测量**：布局耗时、首帧渲染耗时、平移帧率、编辑响应
- 产出**规模上限建议**：在哪一档开始出现可感知卡顿（<50fps），此时应启用什么降级（LOD 更激进 / 切 Canvas / 提示用户）
- 数据落档 `docs/preview/perf-baseline.md`（含测试可复现命令）

## 硬约束

1. **空闲 CPU ≈ 0 是硬验收**——任何动画/tick 结束后必须归零，不得引入永续 rAF 或轮询
2. **冻结合规**（ADR-0004）：新增可选参数/导出 = minor（直接做）；改既有公开签名 = **major，须先写 ADR 再实施**，判断不准时按 major 处理（先问）
3. 测试基线不回归：kernel 273 + react 136 起（本阶段新增测试只增不减）
4. 组件内零硬编码视觉值（延续 K3 纪律：色值只在 `theme/tokens.ts`）；动画时长/缓动建议也走令牌或常量集中管理
5. 不破坏透传铁律与三主题形态
6. 每任务一个 commit：`M5: TX ...` 格式
7. 中文注释；发现既有 bug 只记录不改（除非它阻塞本任务）
