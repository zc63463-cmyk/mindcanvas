## 3. DF-R2 / P2：文件句柄身份仍跟随当前夹具变化

位置：`tools/verify-release-123.mjs:193–216`。

`makeHandle(name, kind)` 只闭包捕获 kind；`getFile()` 和 `createWritable()` 仍实时调用 `scopeOf(kind)`，它读取 `window.__fixtureKind`。这没有满足 T1“创建句柄时固定文件身份”的要求。

独立探针执行了正式脚本原样提取的 `page.addInitScript`，并使用同一 `WRITE_LEDGER_SOURCE`：

```text
在 main 创建 handle，首次读取：MAIN FILE
切 __fixtureKind=pure，再用同一 handle 读取：PURE FILE
用同一旧 handle 写入并 close：committed.scope = md:pure
正确期望：同一 handle 仍读写 main
readIdentityPreserved=false / writeIdentityPreserved=false
```

证据：`audit.mjs` / `audit.json`。这是验收替身串档，不是本轮发现产品保存协调器串档；无需重写包 1。

**修复出口：** 创建 handle 时捕获不可变 scope、原始内容与目的地身份，后续 getFile/createWritable 均只用该身份。用真实注入函数验证旧句柄跨夹具切换、已创建 writable 延迟 close，以及两个目的地隔离。保留 pending/committed 语义，再跑受影响 R1/R3/R6 与相关负控。
