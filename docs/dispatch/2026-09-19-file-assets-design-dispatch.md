## 1. 任务与停止点

交付一套基于当前实现、可以拆成后续开发包的产品与技术设计。目标是让用户找得到文件、知道保存在哪里、改名移动后仍能可靠保存，以及找得到图片、知道图片归属、重开文档不意外丢图。

本包只做代码调查、设计文档、文字线框和开发拆分，不实施功能、不迁移数据、不修改产品源码/测试/门禁/验收工具，不提交、暂存、推送或发布。最终状态为“设计候选可复核”，不得自动进入实施。

推荐由一个外派设计负责人统一完成 D0–D3，先明确共享契约再深化两个模块；后续开发包可按契约拆开。本任务书不是已批准的最终产品规格，设计者需要比较方案并作出有依据的推荐。

## 4. D0：现状、共享身份与架构选择

先完成能力矩阵：导图/自由画布 × 单文件/目录工作区/浏览器文档库 × 原生文件接口可用/不可用。每格标为已有、部分支持、无入口或待验证，附依据。不假定两种画布共享全部图库和文件管理入口。

画出“打开/保存/另存为/重开”和“上传/插入/解析/导出”的现有数据流。明确以下概念的区别和生命周期：

1. 逻辑文档身份、一次编辑会话、内容版本、保存目的地、句柄对象、显示名称和路径。
2. 工作区身份、文档库记录身份、最近项/收藏身份；同一个文件取得新句柄不应仅因对象变化成为另一个文件，同名文件也不能自动视为同一个。
3. 资产身份、资产存储归属、文档中的序列化引用、磁盘相对路径、临时 object URL、内联 SVG。URL 不能成为持久身份。
4. 引用索引的覆盖范围与可信度：仅当前文档、已知文档、完整扫描或未知。未知不能推断为“无人引用”。

比较至少三个方案：A 路径加作用域的最小修补；B 显式作用域/稳定索引与兼容引用的渐进增强；C 自包含项目包。按兼容成本、外部改名/复制可识别程度、无工作区场景、迁移风险和可验证性比较。

优先评估 B，允许证据支持更小方案；不得预设必须重写全部 Markdown/JSON 格式或引入数据库服务。真实文件身份识别需说明浏览器能力及边界，不能直接把验收替身的 `open:`/`save:` 标签当生产设计。

给出接口草案与状态图：操作开始前校验、I/O、成功回填、部分成功、取消、失效和失败。说明每个接口由哪层负责，不只列类型名称。

## 5. D1：文件管理增强设计

### 用户流程

- 信息架构：真实工作区、浏览器文档、最近与收藏的入口关系；搜索范围、当前文档标识、路径/保存状态、空态和错误态。
- 新建、打开、改名、移动、复制、删除及重新定位逐项设计；标明现有与新增。区分改文件名和改文档内部标题，给出同步或不自动同步的规则。
- 导图与自由画布的文件类型、默认扩展名、可打开项及不支持文件的反馈。
- 搜索/筛选/排序、键盘导航、上下文菜单、拖放反馈和无障碍焦点；批量操作是否进入首期须单独论证。
- 删除当前文件或包含它的目录：列出草稿、未保存模型、在途写入的处理选择。永久删除前的确认与恢复能力需匹配实际平台，不能声称浏览器删除自带回收站。

### 一致性与失败

- 改名/移动当前文档必须明确如何等待已有写入、抑制新的自动保存、更新目的地，再恢复编辑；引用现有离开/保存接口，避免另起不兼容的清脏逻辑。
- 复制后删除不是原子移动：逐阶段规定结果与重试行为。目标已创建但源删除失败时不能假装全失败、盲目重试覆盖或显示全成功。
- 同名冲突、大小写差异、权限撤回、外部改动/删除、目录失联、目录扫描失败、取消选择器、重复点击和迟到回调都要有明确状态。
- 明确新目的地何时生效，取消/失败是否保留旧目的地，部分成功由谁决定继续编辑哪一份。最近项、收藏、选择项和资产相对引用同一方案更新。
- 文件移动尤其要核实嵌套目录下资产路径的真实解析基准；未知外链不静默改写。

产出至少主面板、改名/冲突、移动部分成功、失联重新定位四类文字线框；写出用户能理解的提示，不把内部 ID 或技术错误直接当 UI 文案。

## 6. D2：图库与资产管理增强设计

### 发现与使用

- 明确“内置素材”“浏览器素材”“当前工作区资产”“当前文档使用中”的关系，判断是否应作为范围、筛选或不同入口；避免一屏重复列出相同资产。
- 基于既有搜索/收藏/网格/列表，设计预览、名称、类型、尺寸/大小、来源、排序、空态与失效态；缩略图懒加载/分页要有代表性数据集和拟定目标，不能报未经测量的性能。
- 定义 icon/media/child 插入的适用位置、目标选中态、成功反馈与撤销；自由画布需单独确认能力与缺口。
- 设计同名“保留两份/显式替换/取消”，不要静默覆盖。同内容去重与同名不同内容分开，给出作用域与是否影响既有引用的规则。

### 归属、生命周期与引用

- 上传返回结果区分“已持久化”“仅当前会话可用”“失败”，明确插入是否可继续及重试/导出补救入口；不把显示成功当作保存成功。
- 工作区切换、组件卸载、资产替换后的 object URL/cache 生命周期；异步列表、上传与读取结果必须核对作用域代次后回填。
- 分别设计移除节点引用、取消收藏、删除图库记录、删除实际资产文件；引用影响确认、失效后重新定位、撤销边界和恢复能力均需明确。
- 引用来自未打开文档或外部程序时，若无法完整证明无引用，就标“引用范围未知”，首期不得自动垃圾回收。
- 新建/另存为/复制文档/跨目录移动时，资产是共享、复制还是重新绑定？浏览器本地资产在另一浏览器/设备不自动存在，不能仅因文档保存成功宣称可携带。
- 区分位图、大 SVG、内联 SVG、远程 URL 的加载/持久化/导出口径；沿用现有安全边界，说明新入口如何避免执行不受信任的 SVG 内容。

产出图库主界面、详情/引用、同名处理、存储失败、断图修复至少五类文字线框；“便携项目导入/导出”先给契约与后续切片，不在本包落地。

## 7. D3：兼容、联合验收与实施拆包

### 兼容与迁移

列出旧文档引用、全局文件名资产键、浏览器最近项/收藏、目录 assets 与已有句柄的迁移表：旧格式识别条件、新表示、惰性或批量迁移、失败续跑、幂等、保留原数据及版本回退策略。无法确定归属的旧数据不得按猜测自动合并或删除。

能力降级表至少覆盖文件系统 API 不可用、权限未授予/已撤回、IndexedDB 写入失败、浏览器数据被清理、目录脱离和离线。逐项说明可用操作、提示与恢复路径；不把尚未验证的跨浏览器支持写成事实。

保留既有契约：downloaded 不等于磁盘已保存；写盘事实与附属元数据警告分开；内容/会话归属匹配才清脏；IME 与隐藏草稿须正确提交；flush 的 failed 不作真值成功；离开决策单请求并在每个异步边界校验归属。端口方法通过箭头包装避免丢失 this。不要通过统一新控制器重写已验收生命周期来扩大本包范围。

### 联合验收清单（设计交付，不要求本包实跑）

至少给下列场景写出前置条件、用户动作、可观察结果、适当测试层、故障注入和能命中该守点的负控。区分自动化与人工验收，系统选择器真实手势和真实输入法不能用替身冒充。

| 编号 | 必须覆盖的场景 | 关键判据 |
|---|---|---|
| F1 | 当前文档 dirty 且正在写入时改名/移动 | 新旧目的地写入归属明确，最新内容不丢，不误清脏 |
| F2 | 删除当前文档或其父目录，含隐藏草稿/组合输入 | 用户决定前不丢草稿，取消可继续；显式放弃的边界清楚 |
| F3 | 移动目标写成、源删除失败 | 呈现两份及部分成功，不盲目覆盖重试 |
| F4 | 权限撤回、外部改名或目录失联后重新定位 | 不把失败写成已保存；旧记录恢复或解除关联可解释 |
| F5 | 同名文件位于不同目录/新句柄指向同一文件 | 区分显示名和真实身份；收藏/最近/当前项不串文件 |
| A1 | 两工作区都有 assets/a.png，连续切换并出现迟到结果 | 预览和插入来自当前作用域，无缓存串图 |
| A2 | 同名不同内容上传、选择保留两份/替换/取消 | 既有引用的变化符合选择；取消无写入 |
| A3 | IDB/磁盘写入失败，但 object URL 可用 | 可见区分会话可用与持久化；刷新恢复预期明确 |
| A4 | 删除被当前/未打开/未知文档引用的资产 | 不把未扫描等同未引用；删除影响与恢复边界可见 |
| A5 | 嵌套目录文档移动、复制、另存为，包含相对图片引用 | 保存后实际重开按既定资产规则显示，源文档不被意外改写 |
| A6 | 存有浏览器资产的文档换浏览器或清空本地数据 | 缺失可诊断和补救，不冒称单文件可携带 |
| A7 | 小 SVG、大 SVG、位图和断链远程图 | 实际存储落点、预览和导出行为与说明一致 |
| X1 | 导图和自由画布各完成“创建→插图→保存→关闭→重开” | 使用产品入口、读实际成功快照、内容与资产一致 |
| X2 | 资产替换/删除与文档 Undo/Redo、保存重开交叉 | 明确模型撤销能否恢复外部文件，不能承诺无法恢复的数据 |

映射既有测试入口，优先扩展有代表性的行为用例：canvas 的 `file-manager-tree.test.tsx`、`file-manager-dialogs.test.tsx`、`save-destination.test.tsx`、`mode-guard.test.tsx`；react 的 `directory-host.test.ts`、`doc-library.test.ts`、`asset-panel*.test.tsx`、`asset-host.test.ts`、`idb-asset-host.test.ts`、`workspace-asset-host.test.ts`、`asset-diagnostics.test.ts`、`asset-broken.test.tsx`、`asset-virtual.test.tsx`、`nodeg-asset.test.tsx`。设计者核对实际文件名和当前断言，不能仅贴文件清单代替验收设计。

### 推荐实施顺序

| 阶段 | 结果导向 | 首要边界 |
|---|---|---|
| P0 可靠性 | 文件操作与保存身份一致；资产作用域隔离、同名策略、真实持久化反馈 | 不重写全部格式，不建云同步，不自动清理未知引用 |
| P1 日常工作流 | 导航/检索/预览/引用影响/断图恢复；两种画布能力对齐 | 每个新增入口都有失败与取消流程；不以 UI 翻新替代可靠性 |
| P2 可携带性 | 文档与资产的可携带打包及导入恢复 | 依赖 P0/P1 契约；先明确重复导入、版本兼容、冲突和外链范围 |

最终把 P0–P2 拆成有顺序、互不争抢核心接口的开发包。每包列问题、依赖、范围/排除项、文件与接口归属、测试、负控、回执与停止点；区分可并行部分与必须串行的共享改动，不编造精确工期。
