## 2. DF-R5 关闭依据

本轮 R7 独立实测：

```text
A = open:main:release-123.mm.md
B = save:release-123.mm.md
A、B 文件名相同，存储身份不同。
另存为成功后 A 逐字不变；B 后续编辑/保存落在 B，A 仍不变。
A 的 pending 不可读，close 拒绝不推进成功快照，也不改 B。
重新取得 A 的 handle：新对象、同目的地、读回 A 最新成功快照。
```

这修正了上轮“A 和 B 共用 md:main，写 B 后 A 也读出 B”的明确反例。`neg-saveas-share` 只把 B 重新映射到 A，正确期望不变，R1–R6 仍全部通过，证明本次负控命中隔离本身。

接受当前替身用于固定 A/B 场景，不将其当作通用文件系统模拟器。无需为了关闭本项再引入目录选择器或完整虚拟文件系统。

## 4. 保留限制与口径纠正（非返修阻断）

- `open:<bucket>:<name>` / `save:<name>` 是固定场景的目的地标识，不支持判定真实同一路径的 open/save 别名，也不覆盖两个 save 目标同名不同目录。主控没有要求“真实同一路径永不合并”；执行者 §5 的“按复核要求取永不合并”应理解为本夹具 A/B 明确代表两个不同文件。
- R7f 在浏览器里直接调用已注入的 picker/getFile，验证的是新 handle 重读；**不是通过产品打开按钮完成的端到端重开旅程**。真正产品重开链的证据仍归 R1/R6。R7a–R7c 走产品 UI，R7d–R7f 为浏览器内替身契约检查。此区别不影响 DF-R5 关闭。

- 系统文件选择器真实手势、真实 OS 输入法、触控、跨浏览器、离线、跨平台像素金图仍未覆盖。
- Canvas 小写路径命令的非阻断备注保留；当前场景输出范围为已核验的绝对指令。R5c 保证 ≥2 个 depth 命中，不声称三档逐区绘制已完整证明。
