# K2-fix 深度外派任务书：基准测试抗噪声修补

> 用法：将本文件全文喂给执行 agent（Claude Code / Codex / deepseek-harness 等），工作目录设为仓库根（`<workspace>`）。任务书自包含，无需其他上下文。

## 你的角色

你是 mindcanvas 仓库的工程执行 agent。本次只处理一个**验收发现的具体缺陷**——工作量约 15 分钟，精修即可，不做任何清单外的事。

## 背景（30 秒）

mindcanvas 是纯文本思维导图的 headless 内核仓库（pnpm workspace，`packages/kernel` 零 DOM/零 react）。K2 阶段刚交付了布局引擎移植与基准测试，验收复核时发现：**基准测试在另一台机器上 flaky 失败**——内核本身健康，问题纯在测试的采样方法。

## 问题证据（验收实测）

`packages/kernel/tests/benchmark-layout.test.ts` 的线性度测试采用**单次采样**：

```
[benchmark] 500=7.7ms 1000=38.3ms 2000=51.5ms
AssertionError: expected 4.979448399734418 to be less than 3   ← t1000/t500
```

根因：t500 量级太小（7.7ms），单次运行被 GC / JIT 层级切换噪声支配，比率 t1000/t500 失真至 4.98。同一测试在交付机器上通过（500→1000→2000 比率 1.06/2.0）——「换台机器就 flaky」是单采样基准的经典缺陷。**注意：布局内核本身是健康的**（t2000/t1000 = 1.34，O(N) 成立），你修的是测试，不是内核。

## 修复要求（T1-T2）

### T1 · 中位数采样改造

改造 `timeLayout` 及线性度测试：

1. 每个规模（500/1000/2000）**连续跑 5 次，取中位数**——首轮是否丢弃自定，但选择与理由写进代码注释
2. 每个规模点先以**该规模一半大小**做一次预热（对齐现有 50 节点预热思路，解决 JIT 分层导致的规模切换失真）
3. 阈值与断言逻辑不变（比率 < 3；2000 节点 < 500ms）
4. 测试文件顶部 JSDoc 注明方法学（「中位数采样 + 规模化预热，防单次采样噪声」），防止将来被误「简化」回去

### T2 · 报告补录

在 `docs/dispatch/K2-report.md` 末尾追加「K2-fix 补录」小节：记录方法学改造、验收实测数值、以及验收方机器上的原始失败数据（上文证据段）作为动机存档。
